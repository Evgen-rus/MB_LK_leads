# AGENTS.md

## Перед началом работы

- Прочитайте `ARCHITECTURE.md`, затем код и конфигурацию затронутого контура. Карта помогает найти границы; source of truth — реализация, схемы и manifest-файлы.
- Основной backend: `backend/app/main.py`; бизнес-операции и выборки: `backend/app/crud.py`; модели и API-контракты: `backend/app/models.py` и `backend/app/schemas.py`; интеграция Prostats: `backend/app/providers/prostats.py`.
- Frontend находится в `my-app-vite/src/`: `api.ts` — контракт с API, `App.tsx` — composition экранов, компоненты — поведение UI. Локальные runbook-файлы находятся в `docs/`.
- Перед изменением общего API, модели данных, прав, webhook или интеграции найдите всех consumers из `ARCHITECTURE.md` и проверьте их вместе.

## Границы и безопасность

- Не читайте без необходимости и никогда не публикуйте содержимое `.env`, `credentials/`, логов, дампов, файлов БД, токенов, паролей или персональные данные лидов.
- Не добавляйте секреты и реальные пользовательские данные в код, тесты, документацию или Git. Используйте уже настроенные локальные значения окружения.
- Не выполняйте production/deploy-команды, миграции, внешние вызовы Prostats/Telegram/Google Sheets, платные или необратимые операции без явной необходимости и полномочий пользователя.
- Не ослабляйте серверную авторизацию, проверки webhook-секретов, дедупликацию лидов или серверную валидацию только ради UI.
- Все текстовые файлы сохраняйте в UTF-8 без BOM. Кириллицу не транслитерируйте и не заменяйте Unicode-escape; перед завершением проверьте diff на повреждение кодировки.

## Внесение изменений

- Делайте минимальное согласованное изменение в source of truth нужного контура. Не исправляйте соседние находки без запроса.
- Для project-операций учитывайте Prostats и локальную БД; для изменений endpoint — `schemas.py`, `main.py` и `my-app-vite/src/api.ts`; для UI-прав — backend-authorisation, а не только скрытие кнопок.
- Изменения схемы требуют проверки моделей, startup schema-evolution в `main.py`, persistence и consumers. В проекте нет отдельного мигратора.
- При изменении фоновых задач, outbox или XLSX preview учитывайте их процесс-локальные ограничения, перечисленные в `ARCHITECTURE.md`.
- Не обновляйте `ARCHITECTURE.md` автоматически: меняйте его только если задача изменяет устойчивую архитектуру, контракты, инварианты или способ проверки. `README.md` меняйте только при изменении краткого запуска; детальные процедуры — только когда это требует задача.

## Проверки и готовность

- Для frontend-изменений из `my-app-vite` выполните `npm run lint` и `npm run build`.
- В репозитории нет настроенного backend test runner и CI-конфигурации: не выдумывайте команды или покрытие. Для backend-изменений используйте только релевантные существующие проверки и явно сообщайте, что не удалось проверить.
- Задача завершена, когда найден source of truth, изменён минимальный согласованный набор файлов, проверены затронутые контракты/соседние контуры, выполнены доступные релевантные проверки и явно перечислены выполненные и невыполненные проверки.
