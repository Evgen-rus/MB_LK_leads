## ТЗ: роль менеджера (агента) в ЛК и раздел «Агенты» в ЛК админа

### Цель

Добавить в систему новый уровень доступа — **менеджер / агент**, который работает как оптовый закупщик идентификаций: получает баланс от админа, распределяет его между своими клиентами и работает только в рамках закреплённой за ним клиентской базы.
Также добавить в ЛК администратора отдельный раздел **«Агенты»** для управления менеджерами, их балансами и их клиентами.

---

### Кто затронут

* **Администратор**
* **Менеджер / агент**
* **Клиент**

---

### Текущее поведение

* В системе есть админ и клиенты.
* Админ работает со всеми основными сущностями системы.
* Клиенты работают только со своими данными.
* Баланс сейчас существует на уровне клиента.
* Отдельной роли менеджера / агента и отдельного раздела «Агенты» нет.

---

### Желаемое поведение

* В системе появляется новая роль: **менеджер / агент**.
* У админа есть:

  * свои прямые клиенты
  * агенты
  * клиенты агентов
* У каждого агента есть:

  * свои клиенты
  * свой баланс идентификаций
* Админ может начислять баланс агенту. 
* Агент НЕ может начислять баланс. Это делает только Админ
* Клиент всегда закреплён за владельцем:

  * либо за админом
  * либо за конкретным агентом
* Админ может в любой момент:

  * забрать клиента себе
  * передать клиента агенту
  * перевести клиента от одного агента к другому
* При переводе клиента к новому владельцу уже выданный клиенту баланс **переносится как долг на нового владельца**.
* Если новый владелец — **админ**, у клиента просто сохраняется уже имеющийся остаток.

---

## Сценарии

### Сценарий 1. Админ создаёт агента

1. Админ открывает раздел **«Агенты»**.
2. Создаёт нового агента.
3. Агент появляется в списке агентов.
4. У нового агента изначально нулевой баланс.

### Сценарий 2. Админ начисляет агенту баланс

1. Админ открывает карточку агента.
2. Указывает количество идентификаций для начисления.
3. Баланс агента увеличивается.
4. Операция сохраняется в истории.

### Сценарий 3. Агент создаёт клиента

1. Агент заходит в ЛК.
2. Открывает экран **«Клиенты»**.
3. Создаёт нового клиента.
4. Новый клиент автоматически закрепляется за этим агентом.

### Сценарий 4. Агент начисляет баланс своему клиенту

1. Агент открывает карточку своего клиента.
2. Выбирает действие начисления баланса.
3. Указывает количество идентификаций.
4. Система проверяет остаток агента.
5. Если остатка хватает:

   * баланс клиента увеличивается
   * баланс агента уменьшается
6. Если остатка не хватает:

   * операция не выполняется
   * показывается сообщение об ошибке

### Сценарий 5. Админ забирает клиента у агента

1. Админ открывает карточку клиента.
2. Меняет владельца клиента с агента на админа.
3. Клиент пропадает из кабинета агента.
4. Клиент появляется в списке прямых клиентов админа.
5. Текущий баланс клиента сохраняется.
6. Для админа этот остаток считается уже существующим остатком клиента.

### Сценарий 6. Админ передаёт клиента агенту

1. Админ открывает карточку клиента.
2. Выбирает нового владельца — агента.
3. Клиент закрепляется за выбранным агентом.
4. Клиент пропадает из прямых клиентов админа.
5. Клиент появляется у агента.
6. Уже выданный клиенту баланс переносится как долг на нового владельца.

### Сценарий 7. Админ переводит клиента от одного агента к другому

1. Админ открывает карточку клиента.
2. Меняет владельца с одного агента на другого.
3. Старый агент теряет доступ к клиенту.
4. Новый агент получает доступ к клиенту.
5. Уже выданный клиенту баланс переносится как долг на нового владельца.

## Экраны и элементы

### 1. ЛК админа — новый раздел «Агенты»

Добавить в меню ЛК администратора раздел **«Агенты»**.

#### В списке агентов показать:

* имя / название агента
* логин / email
* статус
* текущий баланс
* количество закреплённых клиентов
* дату создания
* действия

#### Действия в списке:

* создать агента
* открыть карточку агента
* редактировать агента
* включить / отключить агента

---

### 2. Карточка агента

В карточке агента должны быть блоки:

#### Основная информация

* имя
* логин / email
* статус

#### Баланс

* текущий остаток агента
* кнопка начисления баланса
* история операций по балансу агента

#### Клиенты агента

* список закреплённых клиентов
* количество клиентов
* переход в карточку клиента

#### Действия

* начислить баланс
* переназначить клиентов
* отключить / включить агента

---

### 3. Экран «Клиенты» у админа

На экране клиентов у админа добавить:

#### Новые поля / элементы

* колонку **«Владелец»** или **«Ответственный»**
* отображение типа владельца:

  * админ
  * агент
* имя текущего владельца

#### Фильтры

* мои клиенты
* клиенты агентов
* все клиенты
* конкретный агент

#### Действия по клиенту

* назначить агенту
* забрать на админа
* перевести другому агенту

---

### 4. Кабинет агента

Агент использует те же базовые экраны, что и админ, но только в рамках своих клиентов.

#### Разделы агента:

* Клиенты
* Проекты
* Идентификации
* Отчёты
* Баланс
* Чёрный список

#### Ограничения:

* агент не видит раздел **«Агенты»**
* агент не видит чужих клиентов
* агент не видит прямых клиентов админа
* агент не может создавать других агентов
* агент не может управлять чужими балансами

---

## Данные и сообщения

### Данные

Для агента показывать:

* текущий баланс
* количество клиентов
* список его клиентов

Для клиента показывать:

* текущий баланс
* текущего владельца

Для админа показывать:

* к кому относится клиент
* баланс агента
* баланс клиента

---

### Сообщения

* **«Недостаточно доступного баланса агента для начисления»**
* **«Нет доступа к этому клиенту»**
* **«Клиент успешно переназначен»**
* **«Баланс успешно начислен»**
* **«Агент успешно создан»**

Финальные формулировки интерфейсных текстов — согласовать при реализации.

## Балансовая логика

### 1. Баланс агента

У каждого агента есть собственный баланс идентификаций.

#### Правила:

* начислять баланс агенту может только админ
* агент не может пополнять баланс сам себе
* агент расходует этот баланс при начислении своим клиентам

---

### 2. Баланс клиента

У каждого клиента есть собственный остаток идентификаций.

#### Источник пополнения зависит от владельца клиента:

* если клиент принадлежит админу — баланс клиенту начисляет админ
* если клиент принадлежит агенту — баланс клиенту начисляет агент

---

### 3. Ограничения начисления

* агент может начислить баланс только своему клиенту
* агент не может начислить больше, чем есть у него на остатке
* клиент не может начислять баланс сам себе

---

### 4. Логика при смене владельца клиента

#### Если клиент переводится:

* с агента на другого агента
* с админа на агента
* с агента на админа

то уже выданный клиенту баланс сохраняется у клиента.

#### Правило учёта:

* если новый владелец — **агент**, этот остаток переносится как **долг на нового владельца**
* если новый владелец — **админ**, у клиента просто сохраняется уже существующий остаток

---

## Ограничения и вне скоупа

В рамках этой задачи **не делаем**:

* создание агентами других агентов
* многоуровневую структуру агентов
* совместное владение одним клиентом несколькими агентами
* отдельный новый интерфейс с нуля для агента
* сложную финансовую модель взаиморасчётов между агентами
* автоматическую бизнес-аналитику по прибыли агента

---

## Критерии приёмки

1. В системе появилась новая роль **менеджер / агент**.
2. В ЛК админа появился раздел **«Агенты»**.
3. Админ может создать агента.
4. Админ может включать и отключать агента.
5. Админ может начислять агенту баланс.
6. У агента есть свой отдельный баланс.
7. Агент видит только своих клиентов.
8. Агент может создавать только своих клиентов.
9. Новый клиент, созданный агентом, автоматически закрепляется за этим агентом.
10. Агент может начислять баланс только своим клиентам.
11. Агент не может начислить клиенту больше, чем есть у него на остатке.
12. При начислении клиенту баланс агента уменьшается.
13. Админ видит:

    * своих прямых клиентов
    * агентов
    * клиентов агентов
14. У клиента в админке отображается текущий владелец.
15. Админ может:

    * забрать клиента себе
    * передать клиента агенту
    * перевести клиента от одного агента к другому
16. После переназначения клиент исчезает у старого владельца и появляется у нового.
17. При переназначении уже выданный клиенту баланс сохраняется.
18. Если новый владелец — агент, сохранённый баланс учитывается как долг нового владельца.
19. Если новый владелец — админ, у клиента просто сохраняется текущий остаток.
20. Агент не имеет доступа:

    * к разделу «Агенты»
    * к чужим клиентам
    * к прямым клиентам админа
    * к созданию других агентов
21. Все ограничения доступа и прав работают на сервере, а не только на уровне интерфейса.
