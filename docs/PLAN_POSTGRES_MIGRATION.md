# План перехода на PostgreSQL

Ниже пошаговый план перехода с SQLite на PostgreSQL, чтобы всё работало
так же, как сейчас, без поломок.

## Важное влияние
- Меняется тип БД и строка подключения.
- Любая существующая локальная `app.db` больше не используется.
- Миграции не применяются: схема создаётся через `create_all`, а минимальные данные — через seed.

## Шаги

1. **Подготовить PostgreSQL — сделано**
   - Установить PostgreSQL локально.
   - Создать базу данных и пользователя.
   - Зафиксировать параметры доступа: host, port, dbname, user, password.
   Фактически:
   host: 127.0.0.1
   port: 5432
   dbname: mb_lk_leads_dev
   user: mb_lk_leads_app
   password: (не указываю)

2. **Настроить `DATABASE_URL` — сделано**
   - В `.env` добавить строку подключения:
     DATABASE_URL=postgresql+psycopg://mb_lk_leads_app:PASSWORD@127.0.0.1:5432/mb_lk_leads_dev
     (вместо PASSWORD подставлен реальный)
   - Убедиться, что приложение читает `DATABASE_URL` (сейчас оно это делает).

3. **Добавить драйвер PostgreSQL — сделано**
   - В `requirements.txt` добавлен `psycopg[binary]==3.3.2`.
   - Зависимости установлены.

4. **Адаптировать создание таблиц — сделано**
   - `models.Base.metadata.create_all()` остаётся для начальной схемы.
   - Миграции `ensure_*` не используются, остаётся только seed.
   - Добавлена модель `ProjectIdMap`, чтобы таблица `project_id_map` создавалась автоматически.

5. **Проверить совместимость запросов — сделано**
   - Прогнаны ключевые CRUD-операции.
   - SQLite-специфичных SQL-запросов в основном приложении не выявлено.

6. **Инициализировать минимальные данные (seed) — сделано**
   - Создана служебная запись `notify_state`.
   - Пользователи из `.env` созданы.

7. **Тестирование — сделано**
   - Backend запущен на Postgres.
   - Пройдены основные сценарии: логин, проекты, лиды, админский раздел.

8. **Очистка и фиксация — сделано**
   - Убедиться, что `app.db` больше не используется.
   - Зафиксировать параметры подключения для dev-окружения.

## Риски и как снизить
- **Средний риск**: возможны ошибки в SQL, отличающиеся от SQLite.
- Снизить риск можно тестами основных сценариев.

## Итог
После перехода приложение работает на PostgreSQL с тем же API и логикой,
а схема создаётся через `create_all`, а минимальные данные — через seed.
