# Контекст продукта: Mad Boss leads (MB_LK_leads)

> Файл собран по фронтенду (`my-app-vite`), типам/API-клиенту (`src/api.ts`), корневому `README.md` репозитория и комментариям в коде. Часть формулировок уточнена **по ответам разработчика** (см. раздел в конце про то, что всё ещё нельзя выдумывать).

## 1. Что это за продукт

Веб-личный кабинет (**Mad Boss leads** — так назван бренд в боковом меню) для работы с **проектами** сбора контактов, просмотра **идентификаций**, **отчётов**, **чёрного списка** телефонов и **баланса** по номерам. Есть отдельный режим **администратора**: список клиентов, их проекты, очередь **изменений от клиентов**, которую обрабатывает администратор, баланс клиентов, расширенные таблицы.

**Идентификации** (в коде и API часто «лиды» / `leads`) — по смыслу это **те же сырые лиды**, что приходят от поставщика, но **привязанные к конкретному проекту** (запись без привязки к проекту в интерфейсе отображается без проекта).

После входа клиент по умолчанию попадает в раздел «Идентификации», администратор — в «Клиенты».

## 2. Технология (кратко)

Одностраничное веб-приложение: **React 19 + TypeScript + Vite**; общение с **REST API** (Bearer JWT в `localStorage`, для скачивания файлов — cookie). Бэкенд в этом же репозитории — **FastAPI** (см. `README.md`). Прод-домен фронта в коде упоминается как `leadrecordwh.ru` (проксирование API через `/api`).

## 3. Роли и доступ

- **Клиент** — обычный пользователь после логина; видит свои проекты, идентификации, отчёты, баланс, чёрный список, техподдержку, интеграции; раздел **«История изменений»** (активность) доступен **только** клиенту, не админу (для админа показывается явное сообщение об ограничении).
- **Администратор** — на бэкенде при выдаче токена: **`is_admin = true` только если `user.id == 1`** (`backend/app/main.py`, эндпоинт логина). В JWT попадает то же значение; **других админов по этому правилу нет**. При **имперсонации** выдаётся токен **без** флага админа (от имени клиента).

Возможности админа (по UI и API): список **клиентов** с агрегатами, **проекты всех клиентов**, **имперсонация** (вход «от имени» клиента через отдельный запрос), **очередь изменений** клиентов, **пауза/возобновление сбора** по клиенту, **баланс** клиента (начисления/списания), админские **идентификации**, **чёрный список**, **отчёты**, история проекта с фильтрами **pending/done**.

**Пауза клиента (ответ разработчика):** админ может поставить клиента на паузу — **все включённые проекты** переходят в паузу, **клиент не может редактировать проекты** (блокировка правок со стороны админки).

**Авто-контроль лимитов (ответ разработчика):** если опция включена, при превышении суммы лимитов **активных** проектов над **остатком** система **отключает проекты**, начиная с **наибольшего лимита**, пока сумма не согласуется с остатком.

**Telegram-уведомления (ответ разработчика + подписи в ЛК):** уведомления по **остатку** уходят в **Telegram-группу клиента**, если назначены **chat ID** и включено «Использовать этот чат для уведомлений»; **технические** уведомления и сценарий, когда группа не настроена — в **общий чат админа** (значение по умолчанию из настроек сервера / env). В коде бэкенда маршрут в группу клиента завязан на поле пользователя `telegram_auto_pause_enabled` (в интерфейсе админки названо про уведомления, не про отдельную «автопаузу»).

У клиента на уровне профиля (`/me`) также бывают: **блокировка изменения проектов** (`projectsMutationLocked`), **уникальные имена новых проектов** — см. код и сценарии в `README.md`.

## 4. Разделы и экраны (карта)

Навигация — **внутреннее состояние** (не отдельные URL-страницы), кроме **`/login`** и **`/`**.

| Раздел в меню | Заголовок экрана | Кто видит | Примечание |
|---------------|------------------|-----------|------------|
| **Клиенты** | Клиенты | Только админ | Дашборд по клиентам, переходы к проектам / изменениям / ЧС / балансу |
| **Проекты** | Проекты | Все | У клиента — свои проекты; у админа — экран с выбором клиента и вкладками (проекты, изменения, события ЧС) |
| **Идентификации** | Идентификации | Все | Таблица с фильтрами по проектам, каналам (B1–B4 и др.), датам; экспорт CSV/XLSX |
| **Отчёты** | Отчёты | Все | Список сформированных отчётов; создание отчёта за период (клиент / админ с указанием клиента) |
| **Баланс** | Баланс | Все | Клиент — сводка и операции; админ — по выбранному клиенту, начисление/списание |

| **Интеграции** | Интеграции | Все | Текст и кнопки про CRM (amoCRM, Bitrix24 и др.): **автоинтеграции в ЛК нет**, подключение только **вручную «под ключ» через поддержку**; формы обращения как на поддержке |

Дополнительно у клиента: в шапке **текущий остаток** и индикатор **долга**, **колокол уведомлений** (с переходом в «Историю изменений»). Содержимое колокола приходит с API; **точные пороги и тексты** для всех типов событий смотреть в бэкенде при необходимости.

**Вход:** экран логина (`/login`), логин/пароль → сохранение токена.

## 5. Сущности и связи (бизнес-языком)

- **Клиент (пользователь ЛК)** — учётная запись с логином, отображаемым именем, профилем (в админке: название, ИНН, телефон, контакт). Связан с **проектами**, **балансом**, **чёрным списком**, **отчётами**.
- **Проект** — единица настройки сбора: **название**, **тег**, **статус проекта** (Активен / На паузе / Удалён), **лимит** и **баланс** в бизнес-смысле считаются в **штуках идентификаций** (по сути **номеров телефонов**), **источник сбора** (Сайты, Звонки, СМС, Ретросайты, Ретрозвонки, Пересечение), **код источника данных B1–B4** — для заказчика это **код канала/источника в его контексте** (дополнительной «человеческой» расшифровки в ТЗ не требуется), **регионы** (режим включить/исключить), **сайты и/или телефоны** конкурентов (в зависимости от типа источника), **имя отправителя SMS** (для СМС), **дни получения** (дни недели). У проекта считаются **номера за период**, **всего**, **доменов/номеров** (количество источников). У клиента в таблице проектов отображаются не все поля админки.
- **Статус отгрузки** в модели/UI (Активна / На модерации / Отключена) — **легаси**; **«На модерации» по процессу не используется**. В рабочем процессе важны **Активен** и **На паузе** у **проекта**: в **Активен** у поставщика проект **включается по API**, **идентификации приходят на вебхук**; **На паузе** — соответственно выключено/не отгружается. Поле `deliveryStatus` в данных может сохраняться для совместимости — не путать с актуальным процессом без сверки с бэкендом.
- **Идентификация** — запись с **датой** (в таблице по умолчанию показывается время попадания в БД), **проектом** (или «—» если не привязано), **каналом** (например B1…B4), **источником** (в UI колонка совпадает с UTM-кампанией из API), **телефоном**. Сырые лиды с вебхука после привязки к проекту попадают сюда же. Внутренний идентификатор в API — `ext_id`.
- **Отчёт** — заявка на выгрузку за период с выбором проектов и формата (CSV/XLSX); в списке — дата создания, период, формат; скачивание через связанный экспорт.
- **Чёрный список** — номера телефонов, дата добавления; у админа виден ещё и клиент.
- **Баланс** — операции **начисление (credit)** и **списание (debit)** с суммой и комментарием; сводка: начислено, списано, ручной баланс, использовано, остаток, признак долга, период.
- **Изменения (админ)** — очередь действий клиента (создание/изменение/удаление проекта, добавление/удаление в ЧС) со статусами **ожидает / выполнено**, снимки «до/после», пакетные создания.
- **История проекта** — события create/update/delete с описанием и режимом актора (клиент, админ, имперсонация).
- **История активности (клиент)** — события по сущностям **проект**, **чёрный список**, **баланс**, **отчёт** с текстовым описанием.

На экране **Клиенты (админ)** у строки выводится вычисляемый **статус строки**: Активен / Нет проектов / Долг / Дожим (логика на фронте: нет проектов, остаток ≤ 0, остаток < 15% от лимита и т.д.).

## 6. Типовые сценарии (по коду)

1. **Вход** — логин/пароль → JWT → редирект на основной экран; выход очищает токен и cookie.
2. **Клиент: работа с проектами** — поиск по названию/ID, фильтр по статусу, календарь периода для метрик, пагинация; создание проекта (модалка); редактирование; просмотр **истории изменений** проекта; переход к **идентификациям** за выбранный период или «за всё время»; удаление проекта; переключение Активен ↔ На паузе; **массовые правки**: дни получения, лимит, телефоны/сайты, регионы, статус. Если админ включил блокировку — создание/редактирование недоступны (тост). Для проектов с источником **СМС** редактирование через ЛК заблокировано с предложением обратиться в поддержку.
3. **Клиент: идентификации** — фильтр проектов и «каналов», период дат, экспорт; переход из таблицы проектов с предзаполненными фильтрами.
4. **Клиент: отчёты** — сформировать отчёт за период, скачать из списка.
5. **Клиент: баланс** — просмотр сводки и списка операций за период.
6. **Клиент: чёрный список** — поиск, добавление номеров, удаление записи.
7. **Клиент: поддержка / интеграции** — отправка сообщения на бэкенд (`/support-message`) с телефоном и текстом.
8. **Клиент: история** — лента событий с фильтрами по дате, сущности, поиску.
9. **Админ: клиенты** — обзор по периоду, создание клиента, редактирование карточки, пауза/возобновление **сбора** по всем подходящим проектам клиента, имперсонация, переход к проектам / очереди изменений / событиям ЧС / балансу.
10. **Админ: проекты** — фильтрация по клиенту, массовые действия, редактирование полей проекта (в т.ч. легаси-поля **статуса отгрузки** в данных), переход к идентификациям клиента и к чёрному списку клиента.
11. **Админ: очередь изменений** — просмотр и **подтверждение (resolve)** записей.
12. **Админ: баланс** — просмотр и создание операций credit/debit.

## 7. Интеграции и внешние системы

По **`README.md` репозитория** (не только по UI):

- **Prostats** — внешний API для операций с проектами (`PROSTATS_TOKEN` и др.); при создании проекта возможно несколько технических проектов на разные коды B1–B4; есть сценарий **уникальных имён** с переименованием в Prostats.
- **Telegram** — уведомления (остаток, автопауза по лимитам, техсобытия) и доставка обращений из поддержки; маршрут в чат клиента vs общий админский — см. §3.
- **Google Sheets** — экспорт (отдельный скрипт в репо, не экран ЛК).
- **Вебхук провайдера** — приём лидов на backend (`POST /api/provider-test/{secret}`), связь с проектом по имени страницы и правилам из README.

Экран **Интеграции** — маркетинговый текст и сценарий «написать в поддержку». **Автоматической интеграции с CRM в ЛК нет**; всё, что выходит за рамки ручной настройки командой, **не заявлено** (ответ разработчика: нет).

## 8. Ограничения и неочевидное

- **Маршрутизация SPA:** почти все разделы без отдельного URL — при обновлении страницы откроется последнее сохранённое в `localStorage` представление (кроме логина).
- **Дубликаты доменов/номеров** между проектами — бэкенд возвращает структурированную ошибку; фронт показывает список конфликтов.
- **Авто-контроль лимитов** — при несоответствии суммы лимитов активных проектов и остатка бэкенд **отключает проекты с наибольшего лимита**; при включении проекта клиентом фронт может показать отказ с текстом про сумму лимитов и остаток.
- Разделы **Обучение** и **Онбординг** — только заглушки в UI; **наполнение и сроки отложены** (ответ разработчика).
- Кнопка **WhatsApp** на экране техподдержки ведёт на **тот же URL, что и Telegram** — **намеренная заглушка**, отдельной ссылки на WhatsApp пока нет.

## 9. Глоссарий

| Как в UI (предпочтительно) | Альтернативные названия в коде/API |
|----------------------------|-----------------------------------|
| Идентификации | лиды, `leads`, таблица `Lead` |
| Проект | `Project`, `/projects` |
| Статус проекта | Активен / На паузе / Удалён |
| Статус отгрузки | Активна / На модерации / Отключена (`deliveryStatus`, **легаси**; в процессе опираться на статус проекта) |
| Источник сбора | Сайты, Звонки, СМС, … (`collectionSource`) |
| Канал (в таблице идентификаций) | код B1–B4, поле `source` |
| Источник (колонка в идентификациях) | в API часто `utm_campaign` |
| Лимит | `dataLimit` (в штуках идентификаций / номеров) |
| Доменов/номеров | количество источников сбора (`sourcesCount`) |
| Чёрный список | `blacklist` |
| Клиент (в админке) | пользователь `UserInfo`, `clientId` |
| Начисление / списание (баланс) | `credit` / `debit` |
| Очередь изменений | `admin/changes`, статусы pending/done |

## Что агенту ТЗ не стоит выдумывать

По ответам разработчика закрыто в том числе: **CRM** (автоинтеграции нет), **WhatsApp** (заглушка = тот же URL, что Telegram), **Обучение / Онбординг** (отложено, без утверждённого содержания).

Остаётся не выдумывать от себя:

- **Детальные пороги и полный перечень типов** уведомлений (колокол, Telegram и т.д.) — при жёстком ТЗ сверять с **бэкендом** и кодом.
