# Аналитика в ЛК

Раздел доступен только администратору (`user.id == 1`). Использует текущий JWT ЛК,
отдельный лениво загружаемый экран и API `/admin/analytics`. Поддомен и второй
backend не нужны. Старое приложение Lead Analytics и его данные не используются.

## Работа

1. Выберите клиента и создайте именованную группу из его проектов. Группы
   аналитики независимы от дневных лимитов; один проект может входить в разные
   группы. Удалённые и Pixel-проекты доступны для исторического анализа.
2. Укажите один или несколько периодов вручную, загрузите клиентский XLSX либо
   выберите Google-таблицу и её вкладку. ЛК подготавливает собственные
   идентификации напрямую из основной БД. Таблица Google читается только при
   подготовке запуска; для чтения сервисному аккаунту нужен доступ к таблице.
3. Проверьте колонки, выполните сопоставление, распределите неизвестные статусы
   и сформируйте аналитику. Сохранённые соответствия общие для всех групп
   выбранного клиента. Начальные соответствия пустые; готовые категории и расчёты взяты из
   Lead Analytics. Пустые статусы обрабатываются исходной логикой.
4. Просмотрите результат и скачайте готовый Excel. Повторный анализ создаёт
   новую запись; изменение группы или таблицы не пересчитывает прошлые отчёты.

Новые проекты автоматически в группу не добавляются. Расформирование архивирует
группу: история остаётся доступной, новые запуски запрещены. Удаление конкретного
отчёта требует подтверждения и не удаляет настройки и остальные отчёты.

В окне «Соответствия статусов» можно добавить статус, изменить его категорию
или удалить правило. Изменение действует для всех групп клиента в следующих
расчётах; готовые отчёты и уже поставленные в очередь задания не пересчитываются.
При переносе старых настроек одинаковые соответствия объединяются. Если один
статус имел разные категории в группах клиента, выберите его категорию явно:
до этого он не получает категорию автоматически. Удалённое правило не
восстанавливается из старых настроек групп.

Готовый отчёт открывается внутри аналитики; в истории используется кнопка
«Открыть аналитику» рядом со скачиванием Excel. Просмотр объединяет KPI,
разрезы и динамику в одном экране. Основные показатели можно дополнить всеми
метриками; поиск работает совместно с фильтрами колонок. Сброс сортировки
возвращает исходный порядок backend. «Статусы» и «Данные» всегда относятся к
общему первому периоду отчёта; строки выдаются с пагинацией.

Календарная иерархия содержит общий диапазон, месяцы и недели, обрезанные
границами каждого месяца и выбранного диапазона. Лимит — 64 сохранённых периода.
Для старых отчётов доступны только сохранённые срезы: недостающий месяц или
неделя отмечается как недоступный, без повторного анализа и изменения Excel.
Цветовые пороги общие с Excel (`report_styles.py`). Выгрузка результатов в
Google не добавлена. Сводка, сравнение и промежуточные файлы отдельно не скачиваются.

## Настройка и ограничения

Установите зависимости из `requirements.txt` в окружение backend. Каталог
данных задаётся переменной `LEAD_ANALYTICS_DATA_DIR`; значение по умолчанию —
`data/lead_analytics` в корне этого репозитория. На VPS задавайте постоянный
абсолютный путь вне каталога заменяемых сборок, доступный пользователю backend
на чтение и запись. Не указывайте каталог старого Lead Analytics.

Там хранятся отдельная SQLite-база, снимки входных данных и готовые Excel-файлы.
Основная БД ЛК используется только для чтения; её схема ради аналитики не
изменяется. Каталог содержит клиентские данные: не публикуйте его через Nginx,
не добавляйте в Git и не выводите содержимое в диагностические логи.

Google использует существующий service account через `GOOGLE_CREDENTIALS_FILE`.
Указывайте абсолютный путь к уже настроенному файлу credentials; секреты не
нужно копировать в исходники. При ошибке Google отчёт не создаётся; можно
исправить доступ либо загрузить XLSX. Автоматической записи в Google нет.
Для выбора вкладки сохраняется снимок книги со всеми её вкладками, как в
исходном Analytics; сопоставление использует одну выбранную вкладку и не
объединяет данные разных листов.

Очередь последовательная и process-local: поддерживается один процесс backend.
Не запускайте несколько Uvicorn workers с этим хранилищем. При перезапуске
ожидающие задания продолжаются, прерванные получают ошибку; частичный анализ
автоматически не повторяется. Администратор запускает его заново. Обработка
Excel использует память процесса: очень большие входы могут потребовать
отдельного worker в будущем; незаметное усечение данных недопустимо.

## Резервное копирование

Согласованный backup включает весь `LEAD_ANALYTICS_DATA_DIR`, а не только SQLite
или только отчёты. Для простого холодного backup остановите backend в
согласованное окно, скопируйте весь каталог в защищённое хранилище и запустите
backend. Сохраните метаданные прав доступа. Не копируйте только активный файл БД
во время записи: при WAL нужны также сопутствующие файлы или SQLite backup API.

Восстановление выполняйте при остановленном backend: восстановите каталог
полностью, проверьте владельца и права и прежнее значение переменной окружения.
После запуска проверьте историю и скачивание известного отчёта. Не смешивайте
базу одного backup с файлами другого.

Эти инструкции не означают выполненный deploy или создание backup. Изменения
VPS, перезапуск production и живую проверку Google выполняют отдельно.

## Локальные проверки

Тестовые зависимости: `venv/Scripts/python.exe -m pip install -r requirements-analytics-test.txt`.
Целевые проверки: `venv/Scripts/python.exe -m pytest tests/lead_analytics tests/test_lead_analytics_auth.py tests/test_lead_analytics_parity.py -q`.
Проверка совпадения Excel использует соседний исходный `Lead_analytics` либо путь
из `LEAD_ANALYTICS_SOURCE`; его данные и настройки не изменяются.
Тесты используют искусственные данные и временные хранилища, без production,
живых Google-запросов и импорта startup основного приложения.

В `my-app-vite`: `npm run lint`, `npm run build` и
`npm run test:e2e -- e2e/analytics.spec.ts`. Браузерные тесты подменяют API
искусственными ответами; работу реального pipeline проверяют backend-тесты.
Покрытие нового контура не означает проверку всего backend ЛК.
