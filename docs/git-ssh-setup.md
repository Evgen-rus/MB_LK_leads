# Настройка SSH-доступа к GitHub и выполнение `git pull`

Инструкция, чтобы заново настроить доступ через SSH на сервере без браузера. Команды примерные; подставьте свои значения там, где указан placeholder.

## 1. Проверить, есть ли ключ
```bash
ls ~/.ssh/id_ed25519.pub ~/.ssh/id_rsa.pub
```
Если нет ни одного файла `.pub`, идём к шагу 2. Если есть — можно пропустить генерацию и перейти к шагу 3 (используя существующий ключ).

## 2. Сгенерировать новый ключ (если нет)
```bash
ssh-keygen -t ed25519 -C "ваш_email_на_GitHub" -f ~/.ssh/id_ed25519 -N ""
```
Все вопросы — просто Enter (оставляем путь и пустую парольную фразу).

## 3. Запустить ssh-agent и добавить ключ
```bash
eval $(ssh-agent -s)
ssh-add ~/.ssh/id_ed25519    # если у вас rsa, то ~/.ssh/id_rsa
```

## 4. Показать публичный ключ и скопировать его
```bash
cat ~/.ssh/id_ed25519.pub
```
Скопируйте всю строку целиком. Пример формата (используйте свой, не этот):
```
ssh-ed25519 AAAA...длинная_строка... комментарий
```

## 5. Добавить ключ в GitHub
- GitHub → Settings → SSH and GPG keys → New SSH key.
- Title: любое имя (например, «NSK MB LK»).
- Key type: Authentication Key.
- В поле Key вставьте СВОЙ скопированный ключ (без переносов и обрезки).
- Сохраните.

## 6. Переключить репозиторий на SSH URL
Посмотреть текущий origin:
```bash
git remote -v
```
Поставить SSH URL (подставьте owner/repo):
```bash
git remote set-url origin git@github.com:<owner>/<repo>.git
# пример для этого проекта:
# git remote set-url origin git@github.com:Evgen-rus/MB_LK_leads.git
```

## 7. Проверить подключение к GitHub
```bash
ssh -T git@github.com
```
При первом подключении будет вопрос про доверие host key → введите `yes`. В ответ должно быть приветствие «Hi <username>!...».

## 8. Выполнить `git pull`
```bash
git pull
```
Теперь должно работать без ввода логина/пароля.

## 9. Если открыли новую сессию и агент «забыл» ключ
Каждый раз после нового входа в shell:
```bash
eval $(ssh-agent -s)
ssh-add ~/.ssh/id_ed25519
```

## 10. Полезные проверки
- Список добавленных ключей в агенте:
```bash
ssh-add -l
```
- Проверить, что origin на SSH:
```bash
git remote -v
```

## 11. Удалить/заменить ключ (при утере/компрометации)
- Удалите соответствующий ключ в GitHub (Settings → SSH and GPG keys).
- На сервере удалите файлы ключа (если нужно) и сгенерируйте новый, повторив шаги 2–8.

## Важно
- Не делитесь приватным ключом (`id_ed25519` или `id_rsa`) ни с кем.
- В GitHub добавляется только публичная часть (`*.pub`).
