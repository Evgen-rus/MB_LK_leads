# Release Notes — 13.05.2026

## Кратко

- Для проектов источника `B4` добавлен системный статус **Блокировка оператора**.
- Backend теперь проверяет активные `B4` проекты у поставщика и отражает внешнее отключение в ЛК.
- Проверка запускается автоматически раз в день в `08:00` по МСК.
- Админ может запустить проверку вручную из экрана проектов.
- При обнаружении блокировки создаётся запись в истории проекта и Telegram outbox-уведомление.
- Во frontend добавлен фильтр по статусу **Блокировка оператора** и подсказка рядом со статусом.
- `ARCHITECTURE.md` обновлён под новый flow.

## Что изменено

### Статус Блокировка оператора

- Добавлен новый output-статус проекта: `Блокировка оператора`.
- Статус видят все роли: админ, агент и клиент.
- Статус является системным: его нельзя выбрать вручную при создании, редактировании или массовой смене статуса.
- Пользователь может перезапустить проект обычным переводом в `Активен`.
- Если поставщик снова отключит проект, следующая проверка опять выставит `Блокировка оператора`.

### Проверка активных B4 проектов

- Backend выбирает только проекты:
  - `status == "Активен"`;
  - `data_source_code == "B4"`;
  - с заполненным `provider_project_id`;
  - без `deleted_at`.
- Для каждого проекта вызывается Prostats `gck_project`.
- Если в ответе поставщика `result.status == 0`, проект локально переводится в `Блокировка оператора`.
- Логика `status: 0 -> Блокировка оператора` применяется только к активным `B4` проектам.

### Плановый и ручной запуск

- На старте backend запускается отдельный daemon-thread проверки.
- Thread спит до ближайших `08:00` по `Europe/Moscow`, не держит DB-сессию во время ожидания.
- После проверки thread снова рассчитывает следующий запуск.
- Добавлен админский endpoint `POST /admin/operator-block-check/run`.
- В админском экране проектов добавлена кнопка **Проверить блокировки B4** с summary результата.

### История и Telegram

- При системном переводе проекта в `Блокировка оператора` создаётся `audit_events` запись.
- Краткое описание истории:
  - `Поставщик отключил проект. Статус изменён системой: Активен → Блокировка оператора.`
- Для каждого заблокированного проекта создаётся отдельное Telegram outbox-уведомление.
- Уведомление уходит в клиентский Telegram-чат, если маршрут настроен; иначе используется общий `TELEGRAM_CHAT_ID`.

### Frontend

- В таблицах проектов добавлен статус `Блокировка оператора`.
- В фильтре статусов добавлен пункт **Блокировка оператора**.
- Рядом со статусом отображается компактная иконка `i` с подсказкой:
  - `В данном проекте мало номеров или мало трафика, поэтому его нужно расширить, чтобы проект снова смог работать. Рекомендуется добавить номера, объединить их в один пул и перезапустить проект.`
- Заблокированные оператором проекты исключены из массового выбора в клиентской таблице.
- Ручной клик по статусу запускает обычное включение проекта через update на `Активен`.
