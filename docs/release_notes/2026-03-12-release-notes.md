# Release Notes — 12.03.2026

## Кратко

- Добавлена **пер-клиентная настройка уникальных имён новых проектов**.
- Если настройка включена, новые проекты создаются с маркером вида **`[MB{id}]`**:
  - пример: `B1_[MB54] Магнум`
  - пример: `B2_[MB55] Магнум`
- Уникальное имя применяется не только у нас в ЛК, но и **дополнительно подтверждается у Prostats** после создания проекта.
- Добавлены **ретраи** при переименовании проекта у поставщика и понятное ожидание в UI: пользователь видит, что нужно подождать несколько секунд.
- При редактировании проекта теперь нельзя удалить:
  - обязательный префикс источника `B1_` / `B2_` / `B3_` / `B4_`;
  - маркер `[MB{id}]`, если проект был создан по новой логике.
- Исправлена обработка входящих идентификаций по webhook:
  - удалённые проекты больше не участвуют в привязке по имени;
  - при нескольких совпадениях по имени backend не падает, лид сохраняется без `project_id`, а в Telegram уходит уведомление в общий чат.

## Где работает

- Backend / API:
  - новые поля в `users` и `projects` для управления уникальными именами;
  - двухшаговое создание проекта для клиентов с включённой опцией:
    - create в Prostats;
    - локальное создание в БД;
    - rename в Prostats в формат `B*_[MB{id}] ...`;
  - ретраи на rename у Prostats;
  - серверная валидация имени при редактировании проекта;
  - безопасная обработка дублей имён в provider webhook.
- Личный кабинет:
  - карточка клиента: новая галочка для уникальных имён;
  - модалка создания проекта: подсказка с примером итогового имени;
  - модалка редактирования проекта: подсказка, что технический префикс удалять нельзя;
  - во время создания показывается, что проект создаётся и уникальное имя подтверждается у поставщика.

## Что изменено

### Backend

- В `users` добавлено поле `unique_project_names_enabled`.
- В `projects` добавлено поле `unique_name_applied`.
- На старте backend новые поля добавляются автоматически через schema-evolution.
- В `POST /projects`:
  - для обычных клиентов поведение осталось прежним;
  - для клиентов с включённой опцией включается специальный поток:
    - проект создаётся у поставщика;
    - создаётся локальная запись и получается наш `project.id`;
    - строится финальное имя вида `B1_[MB54] Магнум`;
    - выполняется `update` в Prostats по `provider_project_id`;
    - только после этого проект считается успешно созданным.
- Добавлены ретраи при `update` имени у Prostats с коротким backoff.
- Если rename у Prostats не подтверждён:
  - пользователь получает понятное сообщение;
  - ошибка пишется в лог;
  - в Telegram отправляется служебное уведомление в общий чат из `TELEGRAM_CHAT_ID`.
- В update проекта добавлена серверная защита:
  - нельзя убрать `B1_...B4_`;
  - нельзя убрать `[MB{id}]`, если проект уже создан по новой логике.
- В webhook провайдера:
  - поиск проекта по имени больше не падает на множественных совпадениях;
  - `Удалён` исключён из матчинга;
  - при неоднозначности лид сохраняется без привязки, а в Telegram уходит уведомление.

### Frontend

- `AdminClientCardModal`:
  - добавлен блок настройки уникальных имён новых проектов;
  - описание с примером `B1_[MB54] Магнум`.
- `AdminCreateClientModal`:
  - такую же опцию можно включить сразу при создании нового клиента.
- `CreateProjectModal`:
  - если опция клиента включена, показывается подсказка, что итоговое имя будет дополнено автоматически;
  - во время создания показывается расширенный статус ожидания.
- `EditProjectModal`:
  - добавлена подсказка, что технический префикс обязателен;
  - фронт дополнительно валидирует, что пользователь не удалил его вручную.
- Обновлены типы API:
  - `MeResponse`
  - `UserInfo`
  - `AdminClientCreatePayload`
  - `AdminClientUpdatePayload`

## Поведение для админа

- В карточке клиента можно включить режим уникальных имён новых проектов.
- Если режим включён:
  - все новые проекты этого клиента получают имя с `[MB{id}]`;
  - правило применяется и в обычном клиентском ЛК, и при работе админа через имперсонацию.
- Если режим позже выключить:
  - у уже созданных проектов маркер `[MB{id}]` остаётся;
  - удалять его при редактировании всё равно нельзя;
  - новые проекты после выключения могут создаваться уже по старой схеме без `[MB{id}]`.

## Польза для заказчика

- Решается основная проблема с одинаковыми названиями проектов, когда провайдер присылает только имя, без `id`.
- Появляется гибкая схема:
  - для клиентов, которых вы ведёте по своим правилам, режим можно не включать;
  - для новых клиентов можно включить гарантированно уникальные имена.
- Уменьшается риск потери лидов из-за неоднозначной привязки по имени.
- Пользователь видит, что создание уникального имени может занять несколько секунд, и не воспринимает задержку как зависание.
