# Release Notes — 30.04.2026

## Кратко

- В историю действий добавлены неудачные попытки создания, изменения и удаления проектов.
- Ошибки проектных операций теперь видны клиенту, админу и агенту, но не попадают в очередь админской обработки изменений.
- Для событий истории добавлен результат операции: **«Успешно»** или **«Ошибка»**.
- Технические HTML-ответы внешнего сервиса очищаются перед показом пользователю.

## Что изменено

### История проектных операций

- Успешные изменения проектов по-прежнему пишутся в `audit_events`.
- Неудачные попытки `create` / `update` / `delete` проектов пишутся в отдельный журнал `project_operation_events`.
- Общая история действий, история проекта и админская история проекта объединяют успешные и неуспешные события.
- Неудачные события отображаются с бейджем **«Ошибка»** и понятным описанием причины.

### Админская обработка изменений

- Неудачные проектные операции не требуют отметки **«Выполнено»**.
- Счётчики pending-изменений в админке не изменились: они продолжают учитывать только реальные успешные изменения из `audit_events`.

### Отображение ошибок

- Если внешний сервис возвращает HTML-страницу ошибки, например `502 Bad Gateway`, история показывает очищенный текст без HTML-тегов.
- Для длинных технических сообщений применяется ограничение длины, чтобы история оставалась читаемой.
