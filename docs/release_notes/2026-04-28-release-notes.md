# Release Notes — 28.04.2026

## Кратко

- По умолчанию на странице проектов показывается **100** строк вместо 50 (клиентский ЛК и админский список проектов клиента).
- В таблицах идентификаций изменён **порядок столбцов**: дата, телефон, канал, источники, проект (в админке далее — ext_id и клиент).
- В таблицах **«Проекты»** у клиента и у выбранного клиента в админке: **ID проекта** вынесен в отдельный столбец (число), добавлена **серверная сортировка** по клику на заголовок столбца; у кнопок сортировки рамка после клика мышью скрыта, при навигации с **Tab** остаётся видимый `focus-visible`.
- Для мобильной версии таблиц закреплены левые ID-столбцы при горизонтальном скролле: проекты в клиентском ЛК, проекты выбранного клиента в админке и список клиентов в админке.
- Сводка **«Клиенты»** в админке: список клиентов в ответе API теперь всегда в порядке **возрастания `user.id`** (1, 2, 3, …), чтобы строки не «прыгали» между обновлениями.
- В админской вкладке **«Отчёты»** добавлен отчёт **по всем клиентам и всем проектам**.
- Поиск в таблицах проектов унифицирован: теперь он срабатывает при вводе с задержкой **400 мс** и ищет строго по **названию проекта**.
- В клиентской таблице **«Идентификации»** добавлен поиск по **телефону** и **источникам**.
- В мобильной версии уменьшен шрифт даты/времени в таблицах **«Идентификации»**, чтобы они визуально совпадали с таблицами **«Проекты»**.
- На странице входа для мобильных экранов увеличен шрифт полей логина/пароля до **16px**, чтобы iPhone/Safari не зумил страницу при вводе.

## Что изменено

### Пагинация

- `ProjectsTable` (вкладка «Проекты» у клиента): начальный размер страницы **100**.
- `AdminClientProjects` (проекты выбранного клиента в админке): начальный размер страницы **100**.
- Варианты 10 / 25 / 50 / 100 в селекторе без изменений; меняется только значение по умолчанию при первой загрузке.

### Порядок столбцов в идентификациях

- **Клиентский ЛК** (`LeadsTable`): `Дата` → `Телефон` → `Канал` → `Источники` → `Проект`.
- **Админский ЛК** (`AdminLeadsTable`): `Дата` → `Телефон` → `Канал` → `Источники` → `Проект` → `ext_id` → `Клиент`.

Логика данных и API не менялись, только отображение.

### Проекты: столбец ID и сортировка

- **Клиентский ЛК** (`ProjectsTable`): перед столбцом «Название» добавлен столбец **ID** — только числовое значение `project.id`, без префикса `id` и без бейджа рядом с названием.
- **Админский ЛК** (`AdminClientProjects`): то же для проектов выбранного клиента.
- **Сортировка** выполняется на **backend** (корректно при пагинации): в query к `GET /projects` и `GET /admin/projects` передаются необязательные параметры `sortBy` и `sortDir` (`asc` / `desc`). Разрешённый набор полей зафиксирован на сервере; по умолчанию порядок как раньше — **новые проекты выше** (`id desc`).
- Сортируемые столбцы в UI: **ID**, **Название**, **Источник**, **Статус проекта**, **Лимит**, **Номеров за период**, **Номеров получено всего**, **Источник сбора**, **Доменов/номеров**, **Дата создания**; первый клик по заголовку — по возрастанию, второй — по убыванию.
- **Доступность**: для кнопок в заголовках таблицы (`.table-sort`) отключён стандартный `outline` при обычном фокусе после клика; для клавиатуры сохранён акцент через `:focus-visible`.
- **Мобильный скролл**: в `ProjectsTable` закреплены чекбокс выбора и столбец **ID**; в `AdminClientProjects` закреплён столбец **ID**, чтобы номер проекта оставался видимым при горизонтальной прокрутке.

### Проекты: поиск

- **Клиентский ЛК** (`ProjectsTable`): поиск больше не отправляет запрос на каждый символ мгновенно; ввод обрабатывается с debounce **400 мс**.
- **Админский ЛК** (`AdminClientProjects`): поиск выбранного клиента теперь тоже срабатывает при вводе с debounce **400 мс**, без обязательного нажатия **Enter**.
- Backend-фильтрация проектов теперь выполняется строго по `Project.name`.
- Поиск по `project.id`, `Project.tag` и `user_id` / ID клиента отключён.
- Плейсхолдеры в UI обновлены: теперь явно указано **«Поиск по названию»**.

### Идентификации: поиск

- В клиентском ЛК (`LeadsTable`) добавлена строка **«Поиск по телефону и источникам»**.
- Поиск срабатывает при вводе с debounce **400 мс** и применяется серверно к таблице `GET /leads`, поэтому корректно работает с пагинацией.
- Backend ищет по телефону (`ProviderLead.phone`, `phones_raw`) и по полям, из которых формируется столбец **«Источники»** (`prov_source`, `subdomain`, а также комбинированное значение `prov_source_subdomain`).
- Поиск влияет только на таблицу идентификаций; экспорт CSV/XLSX остаётся по текущим фильтрам периода, проектов и каналов, без учёта строки поиска.

### Мобильная версия: идентификации и логин

- В `LeadsTable` и `AdminLeadsTable` таблицам идентификаций добавлен CSS-класс `table--leads`.
- В мобильном breakpoint дата и время внутри `DateTimeCompact` для таблиц идентификаций уменьшены отдельно: дата до размера обычной ячейки таблицы, время чуть меньше.
- Это не затрагивает таблицы проектов и не меняет данные/API.
- В `Login.css` для `.login-input` на экранах до **768px** задан `font-size: 16px`, чтобы iOS Safari не включал автоматический zoom при фокусе на полях логина и пароля.

### Клиенты: стабильный порядок по ID

- В `admin_clients_summary` (`crud.admin_clients_summary`) выборка пользователей с ролью `client` дополнена сортировкой **`ORDER BY users.id ASC`**.
- Вкладка **«Клиенты»** (`AdminClientsScreen`) и экраны, использующие ту же сводку (например агентский контекст по данным `fetchAdminClientsSummary`), получают клиентов в предсказуемом порядке; расчёт полей сводки не менялся.
- В `AdminClientsScreen` закреплён столбец **ID** при горизонтальном скролле таблицы, чтобы на мобильных экранах было проще соотносить строку клиента с его идентификатором.

### Отчёты: все клиенты

- В админской форме **«Сформировать отчёт»** в поле «Клиент» добавлен вариант **«Все клиенты»**.
- При выборе **«Все клиенты»** отчёт формируется только в режиме **«Все проекты»**; выбор отдельных проектов отключается, чтобы не загружать большой общий список проектов.
- В истории отчётов такие записи отображаются как **«Все клиенты»**, а скачивание выполняется через общий экспорт без `clientId`.
- Backend принимает `clientId = null` для `POST /admin/reports` только у настоящего админа; агентам общий отчёт по всем клиентам недоступен.
