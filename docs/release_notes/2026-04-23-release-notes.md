# Release Notes — 23.04.2026

## Кратко

- В идентификациях ЛК к полю `Источник` теперь автоматически дописывается номер источника через `_`.
- Для суффикса используется только первое значение `subdomain`, если в нём передано несколько значений через `;`.
- Новое значение применяется единообразно в клиентском, админском и агентском ЛК, а также в экспорте идентификаций из ЛК.
- Отдельно обновлена выгрузка provider leads в Google Sheets: первый номер из `subdomain` теперь добавляется и в колонки `E` / `F`.

## Что изменено

### ЛК и backend

- Backend теперь формирует `utm_campaign` с учётом `subdomain`:
  - если есть `prov_source` и `subdomain` -> возвращается `prov_source_<первое значение subdomain>`;
  - если `prov_source` пустой, но `subdomain` есть -> возвращается только первое значение `subdomain`;
  - если `subdomain` пустой -> поведение остаётся прежним.
- В идентификациях ЛК поле `Источник` показывает уже обновлённое значение.
- Изменение действует одинаково:
  - в клиентском ЛК;
  - в админском ЛК;
  - в агентском ЛК.
- Экспорт идентификаций из ЛК в `CSV/XLSX` теперь использует то же обновлённое значение `utm_campaign`.

Пример:

- было: `autogpbl.ru`
- стало: `autogpbl.ru_78001009841`

### Google Sheets

- В отдельной выгрузке provider leads в Google Sheets обновлён формат колонок:
  - `E` -> полное имя проекта + `_` + первое значение `subdomain`;
  - `F` -> `ГЦК ` + имя проекта без префикса `B1_/B2_/B3_/B4_` + `_` + первое значение `subdomain`;
  - `G` -> исходный `subdomain` без изменений.
- Если в `subdomain` несколько значений через `;`, для `E` и `F` берётся только первое значение с обрезкой пробелов по краям.

## Поведение системы

- Номер источника теперь виден пользователю прямо в поле `Источник`, без необходимости отдельно сверять его по `subdomain`.
- Формат значения стал единым между экраном идентификаций и экспортом из ЛК.
- Для Google Sheets сохраняется полный `subdomain` в `G`, но в человекочитаемых колонках `E` и `F` используется только первое значение, чтобы запись не становилась перегруженной.

## Зачем это нужно

- Делает источник в ЛК и выгрузках более понятным для заказчика и менеджера.
- Позволяет сразу видеть, к какому номеру источника относится идентификация.
- Упрощает чтение Google Sheets: ключевой номер встроен в имя проекта, но при этом исходный `subdomain` не теряется.

## Отдельно по UI-кодам источников

- Во frontend для пользователя коды источников теперь отображаются как `A` / `B` / `C` / `D` вместо `B1` / `B2` / `B3` / `B4`.
- Это только display-слой UI: в API, БД и интеграциях source-of-truth по-прежнему остаётся `B1` / `B2` / `B3` / `B4`.
