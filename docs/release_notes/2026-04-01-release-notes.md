# Release Notes — 01.04.2026

## Кратко

- Добавлен новый админский контур тарифов клиента без изменения старой механики баланса.
- В админском экране `Баланс` теперь можно создавать тарифы и корректировать их внутри самого тарифа с комментариями.
- В админской вкладке `Клиенты` добавлен столбец `Тариф` перед `Остаток`.
- В таблице клиентов и в сводке клиента отображается не сумма всех тарифов, а текущий последний созданный тариф.
- Во фронтенде отключено случайное изменение числовых полей колесом мыши.

## Что изменено

### Backend

- Добавлены новые сущности:
  - `client_tariffs` для хранения отдельных тарифов клиента;
  - `client_tariff_operations` для истории корректировок конкретного тарифа.
- Добавлены новые схемы API для:
  - создания тарифа;
  - списка тарифов клиента;
  - получения одного тарифа;
  - истории операций по тарифу;
  - добавления и списания внутри тарифа.
- Добавлены новые admin-endpoints для тарифов:
  - `GET /admin/clients/{client_id}/tariffs`
  - `POST /admin/clients/{client_id}/tariffs`
  - `GET /admin/tariffs/{tariff_id}`
  - `GET /admin/tariffs/{tariff_id}/ops`
  - `POST /admin/tariffs/{tariff_id}/ops`
- В `admin_clients_summary` добавлен расчёт поля `tariffAmount` для админской сводки клиентов.
- Логика отображения тарифа в клиентской сводке и в таблице клиентов привязана к последнему созданному тарифу:
  - берётся последний тариф клиента по `created_at desc, id desc`;
  - показывается его текущее значение с учётом внутренних доначислений и списаний.

### Frontend

- В `AdminBalance` добавлен новый блок тарифов внутри уже существующего экрана:
  - кнопка `Добавить тариф`;
  - список тарифов выбранного клиента;
  - просмотр истории изменений выбранного тарифа;
  - действия `Добавить` и `Списать` внутри тарифа с обязательным комментарием.
- Старые кнопки `Начислить номера` и `Списать номера` сохранены без изменения логики.
- В `AdminClientsScreen` добавлен столбец `Тариф` перед `Остаток`.
- Если у клиента ещё нет тарифов, в колонке `Тариф` показывается прочерк `-`.
- В сводке клиента на экране `Баланс` поле `Сумма тарифов` заменено на `Текущий тариф`.

### UX / Формы

- Для числовых полей во фронтенде отключено изменение значения колесом мыши.
- Защита добавлена в поля тарифов и в другие найденные `input[type="number"]`, включая:
  - модалки баланса;
  - лимит проекта;
  - массовое изменение лимита;
  - фильтр по `ID пользователя` в истории проекта.

## Поведение системы

- Старая механика баланса клиента не меняется:
  - `client_balance_operations` продолжают работать как раньше;
  - `remaining` и лимит-контроль считаются по старой модели.
- Новый тарифный контур пока существует отдельно от старого баланса:
  - создание тарифа не изменяет старый `remaining`;
  - корректировки тарифа не влияют на старую модель автопаузы и лимит-контроля.
- Для отображения в админских экранах тариф трактуется как отдельный учётный слой.

## Зачем это нужно

- Даёт администратору отдельный и более понятный учёт тарифов клиента без риска сломать текущий баланс.
- Позволяет хранить историю изменений конкретного тарифа, а не только общий поток старых начислений и списаний.
- Устраняет редкий UX-сценарий, когда число в поле могло случайно измениться колесом мыши перед сохранением.
