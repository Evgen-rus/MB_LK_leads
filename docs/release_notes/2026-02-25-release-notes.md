# Release Notes — 25.02.2026

## Кратко

- Завершён перенос проектов в ЛК без пересоздания у поставщика.
- Проекты привязаны к клиентам в нашей БД, после чего ими можно управлять напрямую из ЛК.
- Подготовлен и применён импорт из заполненного JSON-шаблона в таблицу `projects`.
- Подготовлен отдельный backfill-скрипт для привязки исторических лидов из `provider_leads` к проектам по имени.

## Где работает

- Backend / БД:
  - импорт проектов в `projects`;
  - привязка исторических лидов в `provider_leads.project_id`.
- Личный кабинет:
  - управление перенесёнными проектами через стандартные экраны ЛК.

## Что изменено

### Импорт проектов

- Добавлен утилитарный скрипт импорта проектов из enriched JSON в таблицу `projects`.
- Поддержана вставка с автоинкрементом `id`.
- Применены целевые правила заполнения полей:
  - `regionMode = null` -> `region_mode = "include"`;
  - `delivery_status = "На модерации"`;
  - `numbers_today = 0`, `numbers_total = 0`;
  - `days_received` формируется из `days` в формате `Вт. Ср. Чт. Пт. Сб.`;
  - `sources_count` рассчитывается по `sites/phones/sms_sender_name`.
- Импортируются также проекты с `collectionSource = "СМС"` (на уровне БД).

### Привязка исторических лидов

- Добавлен скрипт backfill, который проставляет `provider_leads.project_id` для ранее загруженных лидов:
  - строгое сопоставление `provider_leads.project_name == projects.name`;
  - неоднозначные совпадения (дубликаты имён проектов) пропускаются;
  - есть режим `--dry-run` и подробный лог итогов.

## Операционные заметки

- Импорт/привязка выполняются на стороне нашей БД и не создают проекты у поставщика.
- Для безопасного запуска предусмотрен режим предварительной проверки (`--dry-run`).
- После завершения переноса проекты доступны для дальнейшего управления в ЛК.
