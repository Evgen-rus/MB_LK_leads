# Release Notes — 12.05.2026

## Кратко

- Для клиентов добавлены админские поля **Внутренний идентификатор клиента** и **Ссылка на таблицу**.
- Для клиентов с `unique_project_names_enabled=true` новые проекты теперь создаются с внутренним идентификатором клиента в имени.
- Старый формат с `[MB{id}]` больше не применяется к новым проектам.
- Старые проекты не переименовываются; legacy `[MB{id}]` остаётся поддержанным при редактировании.
- Клиент в ЛК видит обычное имя проекта без внутреннего идентификатора.
- Админ и агент видят полное имя проекта с внутренним идентификатором.
- Периодическая проверка Telegram-сигналов тарифа теперь выполняется для всех клиентов, а не только для клиентов с включённым автоконтролем лимитов.

## Что изменено

### Внутренний идентификатор клиента

- В карточку клиента добавлено поле **Внутренний идентификатор клиента**.
- Пример значения: `[LR193] NL`.
- Поле произвольное: backend только обрезает пробелы и не проверяет формат.
- Поле редактирует только админ.
- Если поле пустое, новые проекты создаются с обычным именем.

### Ссылка на таблицу

- В карточку клиента добавлено поле **Ссылка на таблицу**.
- Это обычное текстовое поле, может быть пустым.
- Можно указать любую ссылку, не только Google Sheets.
- Поле редактирует только админ.

### Имена новых проектов

- Для клиента с включённым `unique_project_names_enabled` и заполненным внутренним идентификатором backend формирует имя до создания проекта.
- Raw-имя в БД/API:
  - `B1_[LR193] NL_Виталий`
- Display для админа/агента:
  - `A_[LR193] NL_Виталий`
- Display для клиента:
  - `A_Виталий`
- В Prostats имя по-прежнему отправляется без `B1_`, потому что источник передаётся отдельным полем `src`.

### Редактирование и отображение

- Для новых проектов сохраняется `projects.client_internal_prefix`, чтобы будущая смена идентификатора клиента не меняла старые проекты.
- Клиентские ответы очищают внутренний идентификатор в проектах, истории и экспортируемых отчётах.
- Админские и агентские экраны показывают полное имя проекта.
- Backend защищает технический префикс проекта от удаления при редактировании.

### Telegram-сигналы тарифа

- Фоновый цикл теперь отдельно проверяет `signal1` / `signal2` / `signal3` для всех клиентов.
- Автопауза проектов по превышению лимитов по-прежнему выполняется только для клиентов с `auto_limit_control_enabled=true`.
- Webhook провайдера по-прежнему не запускает мгновенную проверку сигналов на каждый новый лид.
