# Release Notes — 19.02.2026

## Кратко

- Оптимизирован экспорт отчётов через `GET /leads/export` для `CSV` и `XLSX`.
- Убрана загрузка всего набора лидов в память перед выгрузкой: добавлена чанковая выборка из БД.
- `XLSX` теперь формируется во временный файл и отдаётся через `FileResponse` с автоудалением.
- Добавлено сервисное логирование экспорта в `logs/app.log`:
  - `export_leads_done format=csv|xlsx ...`
  - `export_leads_failed format=xlsx ...`
- Добавлен защитный fallback для некорректного `EXPORT_MAX_ROWS`.

## Где работает

- Backend API: endpoint `GET /leads/export`.
- Клиентские и админские экраны, где пользователь нажимает «Скачать отчёт» / «Скачать».

## Что изменено

### Backend

- В `backend/app/crud.py`:
  - добавлен итератор `iter_provider_leads_for_export(...)` с чанковой выборкой;
  - добавлен маппер строки экспорта `_provider_lead_to_export_row(...)`;
  - сохранена совместимость старого метода `fetch_provider_leads_for_export(...)`.

- В `backend/app/main.py`:
  - CSV выгружается потоково из итератора;
  - XLSX собирается в `Workbook(write_only=True)` во временный файл;
  - временный файл удаляется после ответа через `BackgroundTask`;
  - добавлены логи с количеством строк и длительностью;
  - добавлен fallback для `EXPORT_MAX_ROWS`.

## Влияние на производительность

- Снижен пиковый расход RAM при экспорте.
- Повышена устойчивость при параллельных выгрузках `XLSX`.
- Добавлена наблюдаемость: теперь видно, сколько строк и за какое время реально выгружено.

## Операционные заметки

- Актуальный лимит выгрузки контролируется переменной:
  - `EXPORT_MAX_ROWS` (в `.env`).
- Для сервера с ограниченной памятью рекомендуется повышать лимит ступенчато и проверять логи.
- Чеклист теста сохранён в `docs/export-load-test.md`.
