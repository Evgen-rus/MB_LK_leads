# Release Notes — 26.02.2026

## Кратко

- Добавлен контроль блокировки клиентского раздела проектов при массовой паузе (админ может поставить клиенту паузу и временно закрыть создание/редактирование/удаление проектов).
- На экране админа в разделе «Клиенты» теперь показываются два независимых статуса:  
  - **Сбор данных:** по факту состояния проектов клиента.  
  - **Изменения проектов:** разрешены или заблокированы.
- Улучшена логика действий по кнопке: если клиент уже заблокирован, кнопка сразу переключается на сценарий восстановления/разблокировки.
- Для прозрачности при пустом снимке восстановления теперь безопасно снимается только блокировка (без ошибки 409).

## Где работает

- Backend / API:
  - `POST /admin/clients/{client_id}/collection/pause`
  - `POST /admin/clients/{client_id}/collection/resume`
  - `GET /admin/clients/{client_id}/collection-state`
  - `GET /me`
  - защищённые клиентские mutation-эндпоинты:
    - `POST /projects`
    - `PATCH /projects/{project_id}`
    - `DELETE /projects/{project_id}`
- Личный кабинет:
  - экран админа (`AdminClientsScreen`) — новый статусный блок и метка действия.
  - экран клиента (`ProjectsTable`) — блокировка кнопок и действий при активной блокировке.

## Что изменено

### Backend

- Добавлены поля в пользователя для состояния блокировки раздела проектов:
  - `projects_mutation_locked`
  - `projects_mutation_locked_at`
  - `projects_mutation_locked_by`
  - `projects_mutation_lock_reason`
- Реализован guard на сервере для create/update/delete проектов клиента (если есть блокировка — возвращается 409).
- `admin_get_collection_state` теперь:
  - считает “Сбор данных” по фактическому состоянию проектов (показывает `Активен`, если есть хотя бы один активный проект, иначе `На паузе`);
  - в зависимости от состояния блокировки выбирает действие кнопки `pause/resume`.
- `collection/resume` при отсутствии snapshot больше не режет процесс как ошибку: снимает блокировку и возвращает понятное сообщение.

### Frontend

- `ProjectsTable`:
  - блокирует действия создания/редактирования/удаления/массовых изменений при активной блокировке;
  - показывает баннер с состоянием блокировки.
- `AdminClientsScreen`:
  - отображает статус “Изменения проектов” отдельно от “Сбора данных”;
  - убран отдельный вывод подробной причины блокировки в карточке;
  - скрыт пустой/нулевой статусный ряд после операции (`Выполнено: 0/0...`).

## Поведение для админа

- Кнопка выглядит понятнее:
  - пауза: `Пауза + блокировка раздела проекты`
  - восстановление: `Возобновить сбор и разблокировать проекты`
- При паузе: клиенты видят фактическую блокировку, но в админке управление остаётся корректным.

## Польза для заказчика

- Менее неоднозначное управление массовой паузой.
- Меньше “плавающих” состояний: UI отражает реальный статус проектов и отдельный статус редактирования.
- Безопаснее предотвращение нежелательных изменений в период обслуживания клиента.
