# Release Notes — 25.03.2026

## Кратко

- Изменена логика привязки `provider_leads` к проектам после удаления проекта.
- Проект по-прежнему удаляется сразу:
  - во фронте он считается удалённым сразу;
  - у провайдера удаление вызывается сразу, как и раньше.
- Добавлено grace-окно `48 часов` для хвостовых webhook-лидов:
  - если лид приходит после удаления проекта, backend ещё может привязать его к этому проекту;
  - это работает только пока не истёк `provider_leads_grace_until`.
- Приоритет матчинга сделан безопасным:
  - сначала ищется неудалённый проект по имени;
  - только если активного совпадения нет, используется удалённый проект в пределах grace-окна.

## Что изменено

### Backend

- В модель `Project` добавлены поля:
  - `deleted_at`
  - `provider_leads_grace_until`
- Для существующих БД backend сам добавляет эти колонки при старте без отдельного мигратора.
- При мягком удалении проекта теперь дополнительно сохраняются:
  - время удаления;
  - дедлайн grace-окна для привязки хвостовых лидов.
- При переводе проекта обратно в неудалённый статус grace-поля очищаются.

### Webhook / Provider Leads

- Обновлён матчинг проекта по `payload.page` для входящих provider webhook-лидов.
- Новый порядок такой:
  - сначала матчинг только среди проектов со статусом не `Удалён`;
  - если совпадений нет, матчинг среди удалённых проектов с неистёкшим `provider_leads_grace_until`;
  - если на любом шаге найдено больше одного кандидата, `project_id` не ставится.
- Это позволяет:
  - не терять привязку хвостовых лидов после удаления проекта;
  - не ошибаться в случае, когда клиент удалил проект и быстро создал новый проект с тем же именем.

## Поведение системы

- Если удалён старый проект и создан новый с тем же названием:
  - новый неудалённый проект имеет приоритет;
  - к старому удалённому проекту fallback идёт только при отсутствии активного совпадения.
- Если после удаления проекта лид приходит позже, но в пределах `48h`:
  - он всё ещё может получить `project_id` удалённого проекта.
- Если grace-окно истекло:
  - лид больше не будет матчиться к удалённому проекту;
  - при отсутствии нового активного совпадения он сохранится без `project_id`.

## Зачем это нужно

- Снижает число лидов без `project_id` в хвосте после удаления проекта.
- Сохраняет корректную привязку для контрольной сверки лидов между API провайдера и нашей БД.
- Не ломает текущий UX удаления:
  - пользователь видит проект удалённым сразу;
  - внешний delete в Prostats остаётся мгновенным.
