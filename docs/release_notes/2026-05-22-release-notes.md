# Release Notes — 22.05.2026

## Кратко

Добавили для админа понятную диагностику занятых сайтов и телефонов при создании и редактировании проектов. Клиентский кабинет при этом не меняется: клиенты по-прежнему не видят чужие проекты и чужих клиентов.

## Что изменилось

- В админской карточке истории проекта появился блок **Занятые сайты** / **Занятые номера**.
- Для каждого занятого значения админ видит:
  - сайт или телефон;
  - проект, где это значение уже используется;
  - клиента-владельца проекта;
  - login клиента, если он есть.
- Если Prostats отклонил значение, но в нашем ЛК совпадение не найдено, админ видит понятную пометку: значение занято у провайдера вне нашего ЛК, точный проект неизвестен.
- Подробности сохраняются только для новых операций после обновления.
- Старые события истории открываются как раньше: новый блок появляется только если данные уже есть в snapshot события.

## История проектов

Подробности дублей сохраняются в истории операций:

- при частичном успешном создании или редактировании проекта, когда Prostats принял проект, но исключил часть сайтов или номеров;
- при неуспешном создании или редактировании, если Prostats вернул ошибку занятых сайтов или телефонов.

Админ видит эти данные при открытии карточки:

- **Карточка проекта (Создание)**;
- **Карточка проекта (Изменение)**.

## Приватность клиентского кабинета

- Для клиента поведение не изменилось.
- Клиент видит прежние общие предупреждения и ошибки без раскрытия чужих проектов.
- Клиентская история и карточки событий очищаются от служебного поля `duplicateDiagnostics`.
- Агентам также не раскрываются admin-only подробности по дублям.

## Технически

- Backend формирует admin-only поле `duplicateDiagnostics` в snapshot новых событий.
- Для успешных частичных операций поле сохраняется в `audit_events.after`.
- Для неуспешных операций поле сохраняется в `project_operation_events.request_payload`.
- Поиск дублей для админской диагностики выполняется по неудалённым проектам нашего ЛК.
- При редактировании текущий проект исключается из поиска дублей.
- Frontend показывает блок дублей в `ChangeProjectDiffModal`, только если `duplicateDiagnostics` есть в snapshot.
- Миграция БД не нужна: данные хранятся в существующих JSON snapshot-полях.

## Проверки

- Проверена Python-компиляция изменённых backend-файлов.
- Проверена production-сборка frontend.
- Проверено, что старые карточки без `duplicateDiagnostics` остаются совместимыми.

## Для чего это сделано

- Чтобы админ мог быстро понять, какие сайты или номера заняты и где именно.
- Чтобы не искать дубли вручную по проектам и клиентам.
- Чтобы отличать дубли внутри нашего ЛК от значений, занятых только на стороне провайдера.
- Чтобы сохранить текущую приватность клиентского кабинета.
