# Release Notes — 06.04.2026

## Кратко

- Добавлен новый уровень доступа `agent` между `admin` и `client`.
- В системе появился отдельный контур управления агентами: создание, редактирование, включение/отключение, баланс агента и история его операций.
- Клиента теперь можно закреплять за агентом и переводить между админом и агентами.
- Агент получил manager-доступ только в рамках своих клиентов: проекты, идентификации, отчёты, чёрный список, старый баланс и тарифы.
- Старый баланс и тарифы теперь разведены ещё чётче: агент может начислять старый баланс своим клиентам, а тарифами управляет полноценно в пределах своих клиентов.
- При отключении агента его вход блокируется, проекты его клиентов ставятся на паузу, а редактирование проектов клиентами блокируется.
- При повторном включении агента снимается только блокировка редактирования проектов; сами проекты автоматически не переводятся в `Активен`.

## Что изменено

### Backend

- В модель `users` добавлены поля для agent layer:
  - `display_name`
  - `role`
  - `owner_agent_id`
  - `is_disabled`
- JWT и `/me` теперь возвращают роль пользователя.
- Добавлены server-side проверки manager-доступа:
  - `admin` видит всех клиентов и всех агентов;
  - `agent` видит только своих клиентов.
- Добавлены новые endpoints:
  - `GET /admin/agents`
  - `POST /admin/agents`
  - `PATCH /admin/agents/{agent_id}`
  - `GET /admin/agents/{agent_id}/balance`
  - `GET /admin/agents/{agent_id}/balance/ops`
  - `POST /admin/agents/{agent_id}/balance/ops`
  - `POST /admin/clients/{client_id}/owner`
- В `/admin/users`, `/admin/projects`, `/admin/leads`, `/admin/blacklist`, `/admin/reports`, `/admin/changes/*`, `/admin/clients/summary`, `/admin/clients/{client_id}/balance*`, `/admin/clients/{client_id}/tariffs*`, `/admin/tariffs/{tariff_id}/ops*` добавлены role-aware ограничения по доступным клиентам.
- Старый баланс (`ClientBalanceOperation`) теперь используется и для агентов:
  - админ может начислять и списывать баланс самого агента;
  - при передаче клиента агенту его текущий остаток переносится как долг агента;
  - агент может уходить в минус.
- Ограничения старого баланса:
  - агент может только `credit` своим клиентам;
  - агент не может `debit` старый баланс клиента;
  - админ не может пополнять старый баланс клиента, закреплённого за агентом.
- Тарифный контур распространён на агентский уровень:
  - агент может создавать тарифы своих клиентов;
  - агент может делать `credit` / `debit` внутри тарифов своих клиентов.
- При отключении агента backend:
  - запрещает вход агенту;
  - ставит проекты его клиентов на паузу;
  - включает клиентам `projects_mutation_locked` с причиной `Агент отключён администратором`.
- При повторном включении агента backend:
  - снимает `projects_mutation_locked` у его клиентов только если блокировка была поставлена именно из-за отключения агента;
  - не переводит проекты автоматически в `Активен`.

### Frontend

- В приложение добавлена новая роль `agent` в навигации и bootstrap-логике JWT.
- Добавлен новый экран `Агенты` для администратора:
  - список агентов;
  - создание и редактирование агента;
  - включение/отключение;
  - баланс агента и история операций;
  - список закреплённых клиентов.
- Экран `Клиенты` обновлён:
  - отображается владелец клиента (`admin` / конкретный агент);
  - админ может переназначать клиента между админом и агентами;
  - агент видит только своих клиентов;
  - агенту скрыты действия, не соответствующие backend-правам.
- Экран `Баланс` обновлён:
  - агенту доступно начисление старого баланса своим клиентам;
  - списание старого баланса для агента скрыто;
  - тарифный блок доступен агенту в рамках его клиентов.
- Карточки создания и редактирования клиента адаптированы под роль агента:
  - скрыты админские поля и действия, которые агент не должен использовать;
  - переход в ЛК клиента остаётся у админа.
- Manager-режим для проектов, лидов, отчётов и чёрного списка приведён к единому поведению для `admin` и `agent` с серверными ограничениями по клиентам.

## Поведение системы

- `admin`, `agent` и `client` теперь являются разными ролями на backend и frontend.
- Клиент может быть:
  - прямым клиентом админа;
  - клиентом конкретного агента.
- Минус агента:
  - разрешён;
  - не ставит проекты его клиентов на паузу автоматически;
  - блокирует только новые начисления старого баланса клиентам агента.
- Тарифы по-прежнему не влияют на старый `remaining`, лимит-контроль и автопаузу.
- Автоматическое возобновление проектов после повторного включения агента не выполняется.

## Зачем это нужно

- Даёт отдельный рабочий контур для агентского уровня без смешивания его с клиентским ЛК и без потери полного контроля у администратора.
- Позволяет делегировать работу с клиентами, проектами и тарифами агентам, не открывая доступ к чужим данным.
- Формализует ownership клиента и перенос финансовой ответственности по старому балансу на агента.
- Удерживает критичные ограничения на backend, а не только в UI.
