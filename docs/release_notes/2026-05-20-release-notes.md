# Release Notes — 20.05.2026

## Кратко

Обновили админский дашборд, работу периодов и расчёт полученных данных. Изменения охватывают коммиты с 18.05.2026 по 20.05.2026.

## Что изменилось

- В дашборд добавлена отдельная метрика **Данные за период**.
- Выбор периода на дашборде приведён к общему UX, как в других вкладках ЛК.
- Дефолтный период дашборда теперь **Сегодня**.
- График динамики данных стал интерактивнее:
  - столбцы анимируются при появлении;
  - при наведении и фокусе показывается дата и количество полученных данных;
  - нулевые значения отображаются аккуратнее.
- Тексты на дашборде стали понятнее: вместо технического `provider leads` используется формулировка **получено данных**.
- Из блока проектов убрана лишняя отдельная кнопка системного риска, чтобы дашборд был проще и чище.

## Дашборд

Верхний блок KPI теперь показывает:

- клиентов;
- проекты;
- **Данные за период**;
- данные за сегодня;
- данные за 7 дней;
- данные за 30 дней;
- остаток.

Метрика **Данные за период** считается по выбранным `fromDate` / `toDate`.

Оперативные метрики **Сегодня / 7 дней / 30 дней** остались отдельными и считаются относительно текущей даты.

## Выбор периода

- Дашборд теперь использует общий календарный фильтр периода.
- Доступны быстрые пресеты:
  - `Сегодня`;
  - `Вчера`;
  - `Неделя`;
  - `Месяц`;
  - `За период`.
- Фильтры дашборда по-прежнему сохраняются в браузере.
- При переходе из дашборда в лиды выбранный период передаётся дальше.

## Расчёт данных

- Для `provider_leads` операционная дата в ЛК теперь единообразно считается по `imported_at`.
- Поле `created_at` во frontend-типах лидов теперь отражает дату в ЛК, то есть момент записи в БД.
- В backend добавлен общий helper для даты лидов, чтобы фильтры, отчёты, дашборд и расход за период считались одинаково.
- Для `provider_leads.imported_at` добавлен индекс, чтобы ускорить выборки по периодам.

## Клиенты и финансовые сигналы

- Неактивные клиенты больше не попадают в тарифные риски дашборда.
- В таблице клиентов статус `Долг` и красная подсветка не применяются к клиентам со статусом работы `Неактивен`.
- Финансовые бейджи показываются только там, где они действительно нужны менеджеру.

## Производительность frontend

- Админские и manager-only экраны переведены на lazy loading.
- Клиентский ЛК больше не должен загружать тяжёлые админские экраны в стартовом JS bundle.
- Для новых тяжёлых админских экранов закреплён инвариант: подключать их через `React.lazy` + `Suspense`.

## Для чего это сделано

- Чтобы дашборд показывал выбранный период явно, без смешения с оперативными KPI.
- Чтобы выбор дат выглядел одинаково во всех основных вкладках.
- Чтобы фильтры по датам в лидах, отчётах, проектах и дашборде считали данные по одной операционной дате.
- Чтобы менеджер не видел финансовые риски по клиентам, которые уже переведены в неактивные.
- Чтобы админская часть меньше влияла на загрузку клиентского кабинета.

## Технически

- Затронуты frontend-компоненты дашборда, таблицы клиентов и корневой роутинг `App.tsx`.
- Затронуты backend-расчёты в `crud.py`, API-схемы дашборда и модель `ProviderLead`.
- Обновлён `ARCHITECTURE.md`: зафиксированы правила расчёта дат лидов, lazy loading админских экранов и новая периодная KPI дашборда.
