## Текст для Telegram заказчика без лишних тех. деталей:

### Release Notes — 16.06.2026

Добавили новый источник сбора **Пиксель** и подготовили отдельную выгрузку таких идентификаций в таблицы клиентов.

Что сделали:

**Пиксель как новый источник**
- Добавили отдельный webhook для приёма идентификаций с сайтов клиентов.
- Пиксель-идентификации сохраняются в общем разделе **«Идентификации»**.
- Для Пикселя показываем **Источник сбора = Пиксель**.
- Канал для Пикселя отображается как **—**, потому что он не относится к каналам **A / B / C / D**.
- URL страницы сохраняется и показывается в строке идентификации.

**Проекты с источником Пиксель**
- В проектах появился отдельный фильтр **«Пиксель»**.
- Пиксель-проекты видны по умолчанию вместе с обычными проектами.
- Для Пиксель-проекта домен используется как ключ привязки идентификаций.
- Название и домен Пиксель-проекта защищены от редактирования, чтобы не ломалась привязка входящих данных.

**Как правильно создавать Пиксель-проект**
- Источник сбора нужно выбрать **Пиксель**.
- Название проекта должно быть доменом сайта, например `live.vyshka.su`.
- В поле домена/сайта нужно указать этот же домен: `live.vyshka.su`.
- Без `https://`, без пути страницы и без UTM-меток.
- Именно по этому домену webhook будет привязывать входящие идентификации к проекту.

**Защита от дублей**
- Обычные provider-идентификации по-прежнему дедуплицируются по внешнему ID.
- Для Пикселя сделали отдельную дедупликацию по паре **vid + телефон**.
- Это позволяет сохранить несколько телефонов для одного посетителя, но не создавать повтор одной и той же пары.

**Фильтры и экспорт идентификаций**
- В разделе **«Идентификации»** добавили фильтр по источнику сбора.
- Можно отдельно отфильтровать строки Пикселя.
- Экспорт идентификаций учитывает фильтр **Источник сбора = Пиксель**.
- Остаток и баланс клиента учитывают Пиксель-идентификации так же, как обычные строки.

**Отдельная таблица клиента для Пикселя**
- В карточке клиента добавили поле **«Таблица клиента: Пиксель»**.
- Пиксель не смешивается со старой общей Google-таблицей provider-лидов.
- Для Пикселя подготовлен отдельный cron-экспорт напрямую из ЛК в таблицу клиента.
- Данные раскладываются по листам месяца: например **Июнь 2026**, **Июль 2026**.
- Если наступил новый месяц, скрипт создаёт новый лист и переносит заголовок из предыдущего листа.
- После успешной выгрузки строка помечается в БД, чтобы повторный cron не отправлял её заново.

**Данные в таблице Пикселя**
- В таблицу выгружаются телефон, дата, проект, URL и служебный ID из ЛК.
- UTM-поля берутся из URL: `utm_term`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `yclid`, `aviclid`, `utm_referrer`, `utm_type`, `utm_domain`.
- Если какого-то параметра нет в URL, в таблицу пишется пустое значение.

Теперь Пиксель можно использовать как отдельный источник сбора: идентификации попадают в ЛК, корректно фильтруются, учитываются в балансе и могут выгружаться в отдельные клиентские Google-таблицы.
