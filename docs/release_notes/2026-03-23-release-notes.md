# Release Notes — 23.03.2026

## Кратко

- Добавлен новый админский сценарий для **ручного импорта лидов из XLSX** прямо в личном кабинете.
- Импорт сделан **двухшаговым и безопасным**:
  - сначала выполняется **preview** файла без записи в БД;
  - потом админ отдельно подтверждает **import**.
- Импорт доступен **только авторизованному админу**:
  - новый раздел виден только в админском интерфейсе;
  - backend дополнительно проверяет права через `require_admin`.
- При preview система показывает:
  - сколько строк найдено;
  - сколько строк валидны;
  - сколько дублей уже есть в БД;
  - сколько строк готовы к импорту;
  - есть ли проблемы с привязкой к проектам.
- Импорт блокируется, если в файле есть строки:
  - без однозначной привязки к проекту;
  - с неоднозначным совпадением проекта.
- Сохранён и CLI-вариант импорта из XLSX для служебного использования.

## Где работает

- Backend / API:
  - новый сервис preview/import для XLSX;
  - новые admin endpoint'ы для загрузки файла и подтверждения импорта;
  - временное хранение preview-сессии по `previewId`;
  - повторная серверная валидация данных из файла перед записью в БД.
- Личный кабинет:
  - новый отдельный админский раздел **«Импорт лидов»** в левом меню;
  - загрузка `.xlsx` через интерфейс;
  - просмотр summary и примеров проблемных строк;
  - отдельная кнопка подтверждения импорта.
- CLI / служебные инструменты:
  - сохранён скрипт `tool_import_provider_leads_from_xlsx.py` для ручной работы через серверную консоль.

## Что изменено

### Backend

- Логика импорта из XLSX вынесена в отдельный backend-модуль, чтобы её можно было использовать и из CLI, и из API.
- Добавлены новые admin endpoint'ы:
  - `POST /admin/provider-leads-import/preview`
  - `POST /admin/provider-leads-import/commit`
- В `preview`:
  - файл принимается как upload;
  - проверяется расширение `.xlsx`;
  - проверяется размер файла;
  - создаётся временная preview-сессия с `previewId`;
  - собирается summary по данным файла.
- В `commit`:
  - импорт выполняется только по существующему `previewId`;
  - дополнительно проверяется, что preview был создан тем же админом;
  - перед записью снова учитываются дубли по `vid`.
- Временные preview-артефакты:
  - хранятся ограниченное время;
  - удаляются после успешного импорта;
  - старые preview автоматически очищаются.
- Валидация данных из XLSX использует ту же бизнес-логику, что и CLI-скрипт:
  - `id -> vid`
  - `Проект -> project_name`
  - `Телефон -> phone / phones_raw`
  - `Создано -> prov_created_at`
  - `Комментарий -> subdomain`
- Для `prov_chanel` и `prov_source` используется тот же разбор имени проекта, что и в webhook-потоке.
- Для поддержки upload endpoint'ов добавлена зависимость `python-multipart`.

### Frontend

- В левое меню администратора добавлен новый раздел **«Импорт лидов»**.
- В `App.tsx` подключён новый admin-view и заголовок страницы для этого раздела.
- Добавлен новый экран импорта, на котором админ может:
  - выбрать `.xlsx` файл;
  - выполнить preview;
  - посмотреть summary;
  - посмотреть примеры проблемных строк;
  - запустить import только после успешного preview.
- Во фронтенд API добавлен отдельный helper для `FormData` upload, чтобы не использовать JSON-запрос там, где нужен файл.
- Добавлены новые API-методы:
  - preview XLSX-импорта;
  - commit XLSX-импорта.

## Поведение для админа

- Админ больше не обязан:
  - заходить на сервер по SSH;
  - вручную копировать `xlsx`;
  - запускать импорт через консоль.
- Новый рабочий поток:
  - открыть раздел **«Импорт лидов»**;
  - выбрать файл;
  - выполнить preview;
  - убедиться, что нет проблем с проектами;
  - нажать **«Импортировать»**.
- Если в preview есть:
  - `notFoundProjects > 0`
  - или `ambiguousProjects > 0`
  - import не разрешается до исправления данных.

## Польза для заказчика

- Упрощается восстановление лидов, если webhook недополучил часть данных от провайдера.
- Исчезает лишняя ручная работа через серверную консоль.
- Снижается риск ошибочного импорта:
  - есть preview перед записью в БД;
  - есть серверная защита по роли админа;
  - есть дедупликация по `vid`;
  - import блокируется при проблемной привязке к проектам.
- CLI-инструмент остаётся как резервный служебный вариант, но основной сценарий переносится в админский ЛК.
