## Текст для Telegram заказчика без лишних тех. деталей:

### Release Notes — 08.06.2026

Сегодня расширили аналитику, массовую работу с проектами в админке, уведомления и обработку временных сбоев.

Что сделали:

**Сводка клиента в разделе «Клиенты» (админка)**
- Добавили **среднее за 7 и 3 рабочих дня** (Вт–Сб от текущей даты).
- Появилась разбивка **данных за период по источникам A / B / C / D**.
- Добавили **график динамики за последние 30 дней**.
- Кнопки **A / B / C / D** переключают источники в сводке — показатели и график пересчитываются по выбранным каналам.

**Админский дашборд**
- Новые KPI: **«Среднее 7 раб. дн.»** и **«Среднее 3 раб. дн.»** — по рабочим дням (Вт–Сб).
- Блок **«Блокировки»** теперь открывает **полный список D-проектов в статусе «Блокировка оператора»** с клиентом, проектом, каналом, датой обнаружения и кнопкой перехода в проекты клиента.

**Графики по проектам**
- В **админском** и **клиентском** ЛК появился **график данных проекта** за выбранный период: динамика по дням и разбивка по источникам.
- График открывается из таблицы проектов (кнопка / пункт меню «Показать график данных»).

**Проекты клиента в админке**
- Для **администратора** добавили **массовые операции**: можно выбрать несколько проектов и изменить **дни**, **лимит**, **контакты**, **регионы**, **статус** или **удалить** выбранные проекты. Во время обработки показывается прогресс.
- Проекты в статусе **«Блокировка оператора»** и **«Удалён»** в массовый выбор не попадают.
- **Агент** по-прежнему работает со своими клиентами, но **массовые действия и удаление проектов** ему недоступны.
- Добавили фильтр **«Достигнут дневной лимит»** — показывает проекты, где за выбранный период получено данных **не меньше дневного лимита**.

**Уведомления в Telegram**
- Если проект **достиг 100% дневного лимита** за сегодня, в общий чат уходит уведомление: клиент, проект, канал, лимит и фактический объём. Повтор по тому же лимиту не шлётся; при изменении лимита уведомление может сработать снова.
- В **сигналах остатка тарифа** (когда сообщение уходит в общий чат) теперь показывается **имя клиента**.
- В уведомлениях о **начислениях и списаниях по тарифу** убрали лишнюю строку с номером тарифа — остались клиент, тип операции и сумма.

**Ошибки при недоступности сервиса**
- При сбоях шлюза (**502 / 503 / 504**, в том числе HTML-страница nginx) вместо технического текста показывается понятное сообщение.
- Для **создания и редактирования проектов** — отдельный текст про временную недоступность **сервиса поставщика**.
- Для остальных операций — общее сообщение с просьбой повторить попытку позже.

Теперь в админке проще анализировать клиентов и проекты, быстрее обрабатывать блокировки и дневные лимиты, массово менять параметры проектов и понятнее видеть причины временных ошибок.
