Зайди на VPS LeadRecord и проведи performance-аудит ЛК.

Цель: ускорить реальные пользовательские сценарии без оверинжиниринга и без риска сломать прод.

Проверь в первую очередь:
- открытие списка «Клиенты»;
- сводную клиента;
- «Идентификации»;
- отчёты.

Для каждого замерь:
- время ответа API;
- время SQL;
- объём ответа;
- количество SQL/API-запросов;
- где именно теряется основное время.

Ищи прежде всего:
- медленные SQL и отсутствующие индексы;
- N+1;
- выборку лишних строк/полей;
- отсутствие пагинации;
- повторные API-запросы/refetch;
- тяжёлые React-render/re-render.

Работай по принципу:
baseline → найти главный bottleneck → одно изменение → повторный замер → оставить только если есть доказанный эффект.

ВАЖНО:
- на VPS ничего не ломать и не менять вслепую;
- не менять production-БД/данные;
- не делать миграции, restart/redeploy или опасные нагрузочные тесты без моего отдельного разрешения;
- сначала использовать read-only диагностику;
- не ставить новые сервисы/мониторинг;
- не строить отдельную performance-инфраструктуру;
- не оптимизировать то, что и так работает быстро;
- сложность изменения должна быть оправдана измеримым выигрышем.

Если найдёшь очевидные безопасные улучшения, подготовь изменения в коде и тесты, но production не обновляй.

После каждого существенного улучшения добавляй минимальный regression benchmark/guardrail только там, где это действительно имеет смысл.

В конце дай коротко:
1. что сейчас тормозит;
2. baseline;
3. что предлагаешь изменить;
4. ожидаемый/измеренный эффект;
5. риски;
6. что имеет смысл делать первым.
