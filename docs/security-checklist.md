## Срочно

1. `⚠️` Убрать fallback токена через query-параметр `?token=...`
   - Проверено локально: да
   - Где: `backend/app/main.py:276`, `backend/app/main.py:666`, `backend/app/main.py:1073`
   - Риск: токен может попасть в access-логи прокси/балансировщика и внешние системы логирования.
   - Что сделать: оставить `Authorization: Bearer` (и cookie только для экспорта), query-fallback убрать.

2. `⚠️` Убрать значение по умолчанию для `AUTH_SECRET` и падать при пустом/дефолтном секрете
   - Проверено локально: да
   - Где: `backend/app/auth.py:35`, `backend/app/auth.py:48`, `backend/app/auth.py:59`
   - Риск: если секрет не задан в окружении, JWT подписывается предсказуемым ключом.
   - Что сделать: валидировать `AUTH_SECRET` на старте приложения.

3. `⚠️` Сократить логирование webhook payload/headers
   - Проверено локально: да
   - Где: `backend/app/main.py:218`, `backend/app/main.py:222`, `backend/app/main.py:223`
   - Риск: PII/чувствительные данные в логах (`phones`, `headers`, сырой payload).
   - Что сделать: маскировать/редактировать поля, писать только минимум для диагностики.

4. `⚠️` Не передавать секрет webhook в URL-path в долгосрок
   - Проверено локально: да
   - Где: `backend/app/main.py:212`, `backend/app/main.py:92`
   - Риск: секрет в пути может попасть в access-логи разных уровней.
   - Что сделать: перейти на фиксированный endpoint + секрет в заголовке.

5. `⚠️` Не запускать backend от `root` (prod hardening)
   - Проверено локально: частично (по документации)
   - Где: `docs/deployment-guide.md:94`
   - Риск: при компрометации процесса последствия максимальные.
   - Что сделать: системный пользователь с минимальными правами (`lkapp`), права на нужные директории.
