## 1) Создание новых проектов

### 1.1 Создание одного проекта (один B-код)

**Предусловия:**
- Пользователь авторизован в ЛК.
- Открыта страница «Проекты и каналы».

**Шаги:**
1. Нажать «Создать проект».
2. Заполнить «Название» (например, `тест 14`).
3. Выбрать «Источник сбора» = `Звонки`.
4. Выбрать один B‑код, например `B3`.
5. Заполнить «Лимит» (например, `40`).
6. Ввести минимум 5 номеров (например, 5 строк по 11 цифр, начиная с 7).
7. Выбрать дни сбора (например, ВТ–СБ).
8. Нажать «Создать».

**Ожидаемый результат:**
- Проект создаётся.
- В списке появляется один проект с именем `B3_тест 14`.
- Статус проекта соответствует выбранному.
- Отображается лимит, дни и источники.
- Если часть номеров не принята провайдером — показывается предупреждение.
- Проверить соответствие в лк провайдера или скриптом util_06_prostats_sync_check.py

**Фактический результат:**
- Проект создаётся. +
- В списке появляется один проект с именем `B3_тест 14`.  +
- Статус проекта соответствует выбранному.  +
- Отображается лимит, дни и источники.  +
- Если часть номеров не принята провайдером — показывается предупреждение. + все приняты
- Проверить соответствие в лк провайдера или скриптом util_06_prostats_sync_check.py +

### 1.2 Создание нескольких проектов (B1–B4)

**Предусловия:**
- Пользователь авторизован в ЛК.
- Открыта страница «Проекты и каналы».

**Шаги:**
1. Нажать «Создать проект».
2. Заполнить «Название» (например, `тест 15`).
3. Выбрать «Источник сбора» = `Звонки`.
4. Выбрать B‑коды `B1`, `B2`, `B3`, `B4`.
5. Установить «Лимит» (например, `100`).
6. Ввести минимум 5 номеров (например, 5 строк по 11 цифр, начиная с 7).
7. Нажать «Создать».

**Ожидаемый результат:**
- Создаются отдельные проекты для каждого B‑кода:
  - `B1_тест 15`, `B2_тест 15`, `B3_тест 15`, `B4_тест 15`.
- Лимит распределяется между проектами равномерно.
- Если один из проектов не создаётся у провайдера — остальные всё равно сохраняются.
- Появляется уведомление с результатом по каждому проекту (создан/не создан/частично принят).

### 1.3 Создание проекта с конфликтными номерами

**Предусловия:**
- У пользователя уже есть проект со списком номеров.

**Шаги:**
1. Нажать «Создать проект».
2. Выбрать «Звонки», B‑код `B3`.
3. Ввести номера, часть из которых уже используется в другом проекте.
4. Нажать «Создать».

**Ожидаемый результат:**
- Проект создаётся, если провайдер принял запрос.
- Номера, которые не принялись, удаляются из проекта.
- Показывается предупреждение с перечнем непринятых номеров.
- Если провайдер вернул ошибку — показывается сообщение «занято у провайдера» без деталей.

## 2) Редактирование существующих проектов

### 2.1 Изменение лимита и статуса

**Предусловия:**
- Есть существующий проект со статусом «Активен».

**Шаги:**
1. В списке проектов нажать «Настройки».
2. Изменить «Лимит» (например, +10).
3. Изменить «Статус» на «На паузе».
4. Нажать «Сохранить».

**Ожидаемый результат:**
- Кнопка «Сохранить» блокируется, появляется индикатор «Ждём ответ от провайдера…».
- После ответа модалка закрывается.
- Проект в списке обновлён: новый лимит, новый статус.

### 2.2 Обновление списка номеров (часть номеров не принимается)

**Предусловия:**
- Есть существующий проект со списком номеров.

**Шаги:**
1. В списке проектов нажать «Настройки».
2. Добавить несколько новых номеров.
3. Нажать «Сохранить».

**Ожидаемый результат:**
- Если часть номеров не принята провайдером:
  - модалка закрывается после ответа;
  - показывается предупреждение с непринятыми номерами;
  - в проекте остаются только принятые номера.

### 2.3 Редактирование при конфликте у провайдера

**Предусловия:**
- Есть существующий проект со списком номеров.

**Шаги:**
1. В списке проектов нажать «Настройки».
2. Добавить номера, которые у провайдера уже заняты.
3. Нажать «Сохранить».

**Ожидаемый результат:**
- При ошибке провайдера:
  - отображается сообщение о конфликте;
  - если конфликт не найден в нашей БД, показывается «Занято у провайдера. Подробности недоступны.»
  - изменения не сохраняются.
