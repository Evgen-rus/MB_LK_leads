## 5) Лимиты: управление остатком по ЛК + автоматика отключения проектов

### 5.1 Принцип
**Ключевое:**
- Контроль делаем по **остатку ЛК клиента**, а не по каждому проекту отдельно.
- Автоматика работает предсказуемо и объяснимо.

---

### 5.2 Автоматическое отключение проектов по сумме дневных лимитов (MVP)
**Контекст:**
- У каждого проекта задан `daily_limit` (максимум данных/номеров в день).
- У клиента есть `balance_left` (остаток ЛК).

**Цель:**
- Не допускать ухода в минус: если остатка не хватает на потенциальную выдачу по включённым проектам — отключать часть проектов.

**Входные данные:**
- `balance_left`
- список включённых проектов `projects_active[]`
- для каждого проекта: `daily_limit`, `is_enabled`

**Триггер:**
- `sum_daily_limit = Σ daily_limit` по всем включённым проектам.
- Если `balance_left < sum_daily_limit` → запускается автоматика отключения.

**Правило:**
- Отключать проекты до тех пор, пока не станет:
  - `balance_left >= sum_daily_limit` (по оставшимся включённым проектам)

**Алгоритм (MVP):**
1) Посчитать `sum_daily_limit` по включённым проектам.
2) Если `balance_left >= sum_daily_limit` — ничего не делать.
3) Если `balance_left < sum_daily_limit`:
   - пока `balance_left < sum_daily_limit`:
     - отключить один проект по порядку ниже,
     - пересчитать `sum_daily_limit`.
4) Записать событие в аудит + отправить уведомление клиенту.

**Порядок отключения (предсказуемо):**
- MVP: отключать проекты с **наибольшим `daily_limit`** первыми.

**Ограничение автоматики:**
- Автоматика **только отключает** проекты.
- Автоматического включения обратно **нет**.

**Уведомление клиенту (ЛК + внешние каналы):**
- Обязательные поля:
  - причина (остатка недостаточно для суммы дневных лимитов),
  - `balance_left`,
  - `sum_before → sum_after`,
  - список отключённых проектов (название + daily_limit),
  - шаги для продолжения:
    1) пополнить тариф **или** уменьшить дневные лимиты,
    2) затем вручную включить нужные проекты.

**Шаблон:**
> Сработала автоматика: текущего остатка по ЛК недостаточно для суммы дневных лимитов включённых проектов.  
> Остаток: {balance_left}. Лимиты: {sum_before} → {sum_after}.  
> Отключены проекты: {project_list}.  
> Чтобы продолжить: пополните тариф или уменьшите дневные лимиты, затем вручную включите нужные проекты.

**Критерии приёмки:**
- При `balance_left < sum_daily_limit` проекты отключаются до условия `balance_left >= sum_daily_limit`.
- Автоматика не включает проекты обратно.
- Событие и детали фиксируются в аудит-логе.

---

### 5.3 Ручное управление: “включить/выключить клиента” (админ)
**Область применения:** админский ЛК.

**Требование:**
- У каждого клиента в админке есть переключатель:
  - “включить клиента” / “выключить клиента”
- При выключении:
  - отключаются активные проекты/процессы клиента (в рамках текущей архитектуры).
- При включении:
  - восстанавливается состояние: включаются только те проекты, которые были включены до выключения (по истории/снимку состояния).

**Критерии приёмки:**
- Админ выключает клиента одним действием без лишних переходов.
- После включения возвращается прежнее состояние активных проектов.
