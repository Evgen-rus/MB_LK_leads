# ТЗ: доработки проектов, сводки, графиков и уведомлений в ЛК

## Цель

Повысить удобство работы администратора и клиента с проектами и данными по идентификациям.

Администратор должен видеть больше операционной информации в сводке и иметь в админском ЛК такие же ключевые действия с проектами клиента, как сам клиент в своём ЛК.

Клиент должен быстро смотреть динамику данных по конкретному проекту без перехода в отдельные отчёты.

Также нужно улучшить Telegram-уведомления: добавить уведомление о достижении 100% лимита проекта и убрать лишний номер тарифа из уведомления о начислении нового тарифа.

## Кто затронут

* **Администратор** — получает доработки в админском ЛК: проекты клиента, сводка/дашборд, popup по блокировкам, Telegram-уведомление о 100% лимита.
* **Клиент** — получает кнопку с графиком по проекту в клиентском разделе **Проекты**.
* **Агент** — затрагивается только в рамках существующего manager-доступа, если он видит проекты своих клиентов. Отдельные права агента не расширяем без дополнительного согласования.

## Текущее поведение

### Проекты в клиентском ЛК

Клиент может работать со своими проектами: смотреть список, создавать, редактировать, удалять, менять статус, делать массовые изменения и переходить к идентификациям по проекту.

### Проекты в админском ЛК

Администратор работает с проектами клиентов через manager-экран. Нужно проверить, что в админском разделе есть все нужные действия, которые доступны клиенту, и добавить недостающие.

По правке клиента явно требуется:

* массовое изменение проектов клиента из админского ЛК;
* возможность удаления проектов клиента из админского ЛК.

### Админская сводка / дашборд

Сейчас дашборд показывает управленческие показатели, риски, блокировки, источники A/B/C/D и динамику данных.

Нужно расширить сводку дополнительными блоками:

* график по количеству идентификаций;
* график/разбивка по A/B/C/D;
* среднее количество идентификаций в день за последние 7 рабочих дней;
* среднее количество идентификаций в день за последние 3 рабочих дня.

### Клиентский раздел «Проекты»

Сейчас клиент видит список проектов и метрики, но нет отдельной кнопки, которая прямо из строки проекта открывает график по этому проекту.

## Желаемое поведение

### 1. Админский ЛК: действия с проектами клиента

В админском ЛК, в разделе **Проекты**, администратор должен иметь возможность управлять проектами выбранного клиента.

Нужно проверить и при необходимости добавить:

* массовое изменение проектов клиента;
* удаление проекта;
* доступность действий только для администратора в рамках его прав;
* сохранение событий в истории проекта/истории изменений.

Массовое изменение должно поддерживать те же основные поля, что и у клиента, если они уже доступны клиенту:

* дни получения;
* лимит;
* телефоны/сайты;
* регионы;
* статус проекта.

Если какие-то поля фактически отсутствуют или отличаются в текущем админском ЛК, это нужно отдельно зафиксировать при реализации.

### 2. ЛКА: графики и средние значения в сводке

В админскую сводку/дашборд нужно добавить блоки:

1. **График по количеству идентификаций**

   * показывает количество полученных идентификаций по дням за выбранный период;
   * учитывает текущие фильтры дашборда, если они выбраны: период, клиент, A/B/C/D.

2. **График / разбивка по A/B/C/D**

   * показывает распределение идентификаций по каналам A/B/C/D;
   * в интерфейсе показываем A/B/C/D;
   * внутренняя логика должна учитывать, что в данных используются B1/B2/B3/B4.

3. **Среднее за последние 7 рабочих дней**

   * считается по последним 7 рабочим дням по правилу: вторник, среда, четверг, пятница, суббота;
   * воскресенье и понедельник не учитывать;
   * если в периоде есть воскресенье или понедельник, эти дни пропускаются и добираются предыдущие рабочие дни.

4. **Среднее за последние 3 рабочих дня**

   * считается аналогично: только вторник–суббота;
   * воскресенье и понедельник не учитывать.

Правило расчёта среднего:

* берём только дни вторник–суббота;
* считаем сумму идентификаций за выбранные рабочие дни;
* делим на количество рабочих дней, которые попали в расчёт;
* если данных за день нет, но день входит в расчётный рабочий диапазон, считать его как 0, если в продукте уже нет другого правила.

Пример:

Если сегодня вторник, то последние 3 рабочих дня по правилу могут быть:

* вторник;
* суббота;
* пятница.

Понедельник и воскресенье пропускаются.

### 3. ЛКК: график по конкретному проекту

В клиентском ЛК, в разделе **Проекты**, рядом с каждым проектом добавить кнопку для просмотра графика.

Рабочее название кнопки:

* **График**
* или иконка графика с подсказкой **Показать график данных**.

При нажатии открывается popup/модальное окно с графиком по выбранному проекту.

В popup показать:

* название проекта;
* выбранный период;
* общее количество идентификаций за период;
* график количества идентификаций по дням;
* разбивку по каналам A/B/C/D;
* среднее за день по выбранному периоду, если это не усложняет экран.

Период графика:

* по умолчанию использовать период, выбранный в разделе **Проекты**;
* если период не выбран, использовать стандартный период, который уже принят в разделе;
* пользователь должен понимать, за какой период построен график.

Если по проекту нет данных за период:

* показать пустое состояние: **За выбранный период данных по проекту нет**.

### 4. Дашборд: popup по блокировкам

В админском дашборде при нажатии на блок с блокировками нужно открывать всплывающее окно.

Popup должен показывать, какие проекты находятся в блокировке.

В popup вывести:

* клиент;
* проект;
* канал;
* статус: **Блокировка оператора**;
* дата/время обнаружения, если есть в данных;
* действие **Открыть проект** или **Перейти в проекты**.

Важно:

* из popup не нужно менять данные;
* на самом дашборде не добавлять действий, которые изменяют проекты;
* popup нужен только для просмотра и быстрого перехода в нужный раздел.

### 5. Telegram-уведомление: проект достиг 100% лимита

Нужно добавить уведомление в общий Telegram-чат админа, когда проект достигает 100% своего лимита.

Условие отправки:

* у проекта есть лимит;
* количество полученных идентификаций по проекту достигло лимита;
* процент выполнения лимита стал 100% или больше.

Получатель:

* только администратор;
* отправлять в общий Telegram-чат админа.

Клиенту такое уведомление не отправлять.

Рекомендуемый текст уведомления:

Проект достиг 100% лимита

Клиент: [название клиента]
Проект: [название проекта]
Канал: [A/B/C/D, если применимо]
Лимит: [лимит] идентификаций
Получено: [количество] идентификаций

Нужно проверить проект и при необходимости продлить лимит или остановить сбор.

Правило против дублей:

* уведомление не должно отправляться повторно бесконечно при каждом пересчёте;
* после первого достижения 100% по конкретному проекту уведомление отправляется один раз;
* повторная отправка возможна только если лимит проекта был изменён или проект был перезапущен по новому лимиту.


## Сценарии

### Сценарий 1. Администратор массово меняет проекты клиента

1. Администратор открывает админский ЛК.
2. Переходит в раздел **Проекты**.
3. Выбирает клиента.
4. Отмечает несколько проектов.
5. Нажимает массовое действие.
6. Выбирает, что нужно изменить: дни получения, лимит, телефоны/сайты, регионы или статус.
7. Подтверждает действие.
8. Система применяет изменение.
9. Система показывает результат операции.
10. Событие фиксируется в истории.

### Сценарий 2. Администратор удаляет проект клиента

1. Администратор открывает раздел **Проекты** в админском ЛК.
2. Выбирает клиента.
3. Находит нужный проект.
4. Нажимает **Удалить**.
5. Система показывает подтверждение удаления.
6. Администратор подтверждает.
7. Система удаляет проект по текущим правилам продукта.
8. Событие появляется в истории проекта/истории изменений.

### Сценарий 3. Администратор смотрит средние значения в сводке

1. Администратор открывает **Дашборд**.
2. Выбирает период и при необходимости клиента/каналы.
3. Система показывает график по количеству идентификаций.
4. Система показывает разбивку по A/B/C/D.
5. Система показывает среднее за последние 7 рабочих дней.
6. Система показывает среднее за последние 3 рабочих дня.
7. В расчёте не участвуют воскресенье и понедельник.

### Сценарий 4. Клиент смотрит график по проекту

1. Клиент открывает раздел **Проекты**.
2. Находит нужный проект.
3. Нажимает кнопку **График**.
4. Система открывает popup.
5. Клиент видит динамику идентификаций по дням и разбивку по A/B/C/D.
6. Если данных нет, система показывает понятное пустое состояние.

### Сценарий 5. Администратор открывает блокировки из дашборда

1. Администратор открывает **Дашборд**.
2. Видит блок с блокировками.
3. Нажимает на блок.
4. Система открывает popup со списком проектов в блокировке.
5. Администратор видит клиента, проект, канал и статус.
6. При необходимости администратор переходит в раздел **Проекты**.

### Сценарий 6. Проект достиг 100% лимита

1. Система пересчитывает количество идентификаций по проекту.
2. Проект достигает 100% лимита.
3. Система отправляет уведомление в общий Telegram-чат админа.
4. Повторно такое же уведомление по тому же лимиту не отправляется.

### Сценарий 7. Администратор начисляет новый тариф

1. Администратор начисляет клиенту новый тариф.
2. Система отправляет Telegram-уведомление.
3. В уведомлении нет номера тарифа.
4. В уведомлении есть клиент, начисленное количество идентификаций и текущий остаток.

## Экраны и элементы

### Админский ЛК

Разделы:

* **Проекты**
* **Дашборд**
* **История изменений**
* **Баланс / тарифы**

Новые или изменяемые элементы:

* массовые действия в проектах клиента;
* удаление проекта в проектах клиента;
* блок графика по количеству идентификаций;
* блок/график по A/B/C/D;
* показатель среднего за 7 рабочих дней;
* показатель среднего за 3 рабочих дня;
* popup по блокировкам;
* Telegram-уведомление о 100% лимита;
* обновлённый текст Telegram-уведомления о новом тарифе.

### Клиентский ЛК

Раздел:

* **Проекты**

Новый элемент:

* кнопка **График** рядом с проектом;
* popup с графиком по проекту.

### Popup по блокировкам

Нужно проверить проект и при необходимости продлить лимит или остановить сбор.

## Критерии приёмки

1. В админском ЛК в разделе **Проекты** выбранного клиента доступно массовое изменение проектов.
2. В админском ЛК в разделе **Проекты** выбранного клиента доступно удаление проекта.
3. Массовые действия в админском ЛК не применяются к проектам в статусе **Блокировка оператора**, если это противоречит текущим правилам продукта.
4. В админской сводке появился график по количеству идентификаций.
5. В админской сводке появилась разбивка/график по A/B/C/D.
6. Среднее за 7 дней считается по последним 7 рабочим дням по правилу вторник–суббота.
7. Среднее за 3 дня считается по последним 3 рабочим дням по правилу вторник–суббота.
8. Воскресенье и понедельник не участвуют в расчёте средних значений.
9. В клиентском ЛК в разделе **Проекты** у проекта есть кнопка для открытия графика.
10. При нажатии на кнопку открывается popup с графиком по выбранному проекту.
11. В popup по проекту отображаются данные по дням и разбивка по A/B/C/D.
12. Если данных по проекту нет, показывается текст **За выбранный период данных по проекту нет**.
13. В админском дашборде при клике на блокировки открывается popup со списком проектов в блокировке.
14. Popup по блокировкам не изменяет данные, а только показывает информацию и даёт возможность перейти в проекты.
15. При достижении проектом 100% лимита отправляется уведомление в общий Telegram-чат админа.
16. Уведомление о 100% лимита не дублируется бесконечно при каждом пересчёте.
18. Клиенту не отправляется уведомление о 100% лимита проекта, если отдельно не включали такой сценарий.
19. Дашборд не начинает выполнять действия изменения данных напрямую.
