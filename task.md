## Задачи

### 1) Разделить «Создание» и «Изменение»
- Добавить два статуса/типа событий: **«Создание»** и **«Изменение»**.
- В интерфейсе добавить переключатель/фильтр:
  - показывать **«Созданные проекты»** отдельно,
  - показывать **«Изменённые проекты»** отдельно.
- В разделе **«Изменения»** отображать только **фактические изменения**, без созданий.
✅ Сделано — админский кабинет (фильтр «Создание/Изменение», API actions)

### 2) Агрегировать карточки создания
- Если проект(ы) созданы из одного экрана с выбранными источниками **1/2/3/4 (B1/B2/B3/B4)** — отображать **одну** карточку **«Создан проект»** с перечислением источников.
- Убрать дубли **«создан проект»** по каждому источнику, если это **один акт создания**.
✅ Сделано — админский кабинет (агрегация созданий по batch)

### 3) «Идентификации» в админке: выбор клиента и понятность
- Сделать обязательным и очевидным шаг **«Выберите клиента»** (пояснение на экране).
- В фильтрах и списках использовать **«название клиента»**, а не **«логин»** (или показывать оба, но приоритет — **название**).
- Добавить переход в **«Идентификации»** из **«Проектов»** (контекстный переход).
✅ Сделано — админский кабинет (выбор клиента, имя в списках)

### 4) Кликабельность таблицы «Проекты» → «Идентификации»
- Сделать кликабельными:
  - **название проекта**,
  - **название клиента**,
  - **«получено сегодня»**,
  - **«получено всего»**.
- По клику открывать **«Идентификации»** с применением **текущих фильтров** (дата/период), выбранного клиента и выбранного проекта.
- Пример: выбран период **«месяц»**, клик по **«801»** → открыть идентификации с фильтром на эти **801** записи.
✅ Сделано — пользовательский кабинет (кликабельные проекты → идентификации с фильтрами)

  - массово **отключить**,
  - массово **присвоить тег**.
- Сформировать список остальных массовых операций по необходимости (после короткого перечня вариантов).
