Сделал интеграцию создания проекта с Prostats на бэкенде.
Что изменилось
Добавил клиент Prostats: backend/app/providers/prostats.py.
В POST /projects теперь сначала создаём проекты у поставщика, и только при успехе сохраняем локально.
Если Prostats возвращает ошибку (в том числе 422), локальный проект не создаётся.
Ключевое поведение
Маппинг:
Сайты/Ретросайты → type="hosts"
Звонки/Ретрозвонки → type="calls"
Пересечение → type="complex" (только src="bl"/B2)
B1/B2/B3/B4 → rt/bl/mt/mg
status: "Активен" → 1, остальное → 0
content: для hosts/calls — строка через запятую; для complex — JSON‑строка с hosts_content/calls_content/sms_content.
Ошибки дублей: при 422 + “Введите домены/номера телефонов” ищем дубли по type/src и возвращаем список в detail.duplicates.
Важно
СМС пока не поддержан (будет 400), так как у поставщика нет прямого типа для этого режима.
DB‑миграций нет (как ты просил). provider_id пока нигде не хранится.
Если Prostats создал проект, а потом локальное сохранение упало — проект у поставщика останется (редкий кейс).
Как тестировать
1) Убедиться, что в .env есть:
PROSTATS_TOKEN
(опционально) PROSTATS_API_URL
2) Создать проект из ЛК — при ошибках вернётся HTTP 422 с понятным текстом и списком дублей.
Если хочешь, следующим шагом могу:
добавить хранение provider_id (когда будешь готов к миграции);
добавить поддержку СМС/доп. маппингов.
