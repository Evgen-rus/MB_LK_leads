Список задач по итогам встречи
1. Раздел «Клиенты» и сводка
1.1. Внизу раздела «Клиенты» реализовать блок «Итого», который показывает:
суммарное количество данных по всем проектам;
суммарный остаток по всем проектам;
количество проектов по каждому клиенту;
агрегированные показатели по периодам: за сегодня, за вчера, за неделю, за месяц, за выбранный период.

1.2. Обеспечить связь этих показателей с реальными данными бэкенда (убрать «фронтовый» остаток в пользу реального).

2. Процесс обработки «Изменений клиента»
2.1. Реализовать открытие карточки проекта, которую заполнял клиент, в админской части в виде модального окна с полным набором полей.

2.2. Обеспечить возможность удобного копирования данных из этой карточки (визуально 1 в 1 с клиентской формой).

2.3. Разделить логически два процесса:
создание проекта клиентом,
изменение существующего проекта клиентом.

2.4. Учесть сценарий, когда клиент за один раз ставит несколько галочек (V1/V2/V3 и т.п.):
это должно логироваться как одно действие, по которому менеджер создает нужные сущности.

2.5. Внутри карточки изменений добавить кнопку статуса:
«Выполнено» (после выполнения изменение исчезает из списка задач).

2.6. Убрать статус «в работе» из модели; считать задачу либо:
выполненной,
либо нет (если висит в списке).

2.7. Зафиксировать KPI: к 18:00 МСК у менеджера не должно быть незакрытых изменений; предусмотреть техполе/механику для контроля этого в интерфейсе.

3. История изменений
3.1. Добавить подраздел «История изменений» в контексте каждого проекта/клиента (рядом с «Изменения клиента»).

3.2. В «Истории изменений» отображать все изменения с возможностью фильтрации по:
менеджеру (ответственный),
дате,
статусу (сделано / не сделано).

3.3. Обеспечить возможность посчитать количество изменений, сделанных конкретным менеджером за выбранный период.

3.4. Продумать, как удобнее реализовать: отдельной вкладкой контроля или вложенным подразделом внутри проекта, без перегруза интерфейса.

4. Вкладка «Идентификации»
4.1. Обеспечить выбор клиента перед показом данных по идентификациям.

4.2. Реализовать выбор периода:
за день,
за несколько дней,
за произвольный интервал (с календарем).

4.3. Реализовать выбор проектов и добавить кнопку:
«Снять выбор проектов полностью» (сбрасывает все выбранные проекты).

4.4. Уточнить логику кнопок:
оставить три понятные кнопки (например: «Выбрать все», «Снять все», «Применить/Обновить»),
расширить окно так, чтобы по одному выбранному проекту удобно смотреть все идентификации.

4.5. Изменить подпись «Найдено X» на вариант, явно показывающий количество данных по текущим фильтрам:
«Итого данных: X» или «Всего данных по фильтрам: X».

4.6. Гарантировать, что при экспорте отчетов количество выгружаемых строк всегда соответствует этому числу.

5. Отчеты и XID
5.1. Разделить отчеты для клиента и для администратора:
клиент видит только «чистые» данные (без внутренних ID),
админ видит расширенные отчеты.

5.2. Убрать XID:
из таблицы идентификаций в личном кабинете клиента,
из экспортируемых клиентом отчетов.

5.3. Оставить XID:
во внутренних таблицах и отчетах админской части (для сверки данных).

5.4. Реализовать механизм формирования отчетов в админской части:
выбор клиента,
выбор периода,
выбор фильтров,
сохранение набора фильтров,
возможность скачать отчет по этим фильтрам в любой момент.

5.5. В админской части отображать только отчеты, сформированные админом; клиентские отчеты сюда не выводить.

6. Черный список
6.1. Обеспечить выбор клиента и показ его единого черного списка (на все проекты клиента).
 
6.2. Зафиксировать, что черный список привязан к клиенту, а не к проектам.
 
6.3. Учитывать перспективу перехода к схеме «один клиент — один личный кабинет» и возможность работы с общими лимитами на уровне клиента.

7. Баланс
7.1. Спроектировать и реализовать раздел «Баланс» в админской части.

7.2. Баланс должен отображать:
количество приобретенных идентификаций (история покупок/начислений),
текущий остаток идентификаций,
даты операций.

7.3. Привязать эти данные к реальным операциям бэкенда.

8. Обучение / онбординг
8.1. После фиксации интерфейсов спроектировать онбординг:
краткие подсказки по разделам,
сценарии «первого входа»,
минимальные инструкции по работе с идентификациями, изменениями, отчетами, балансом.

9. Личный кабинет клиента
9.1. Зеркально привести интерфейс клиента к логике админской части там, где это уместно (идентификации, отчеты).
 
9.2. Оставить клиенту управление черным списком:
добавление телефонов,
удаление телефонов.

9.3. Проверить, что в клиентском интерфейсе:
нет XID и других внутренних ID,
не отображаются лишние служебные поля.
