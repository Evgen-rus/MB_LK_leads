### Где в проекте формируется админская модалка **«Карточка»** (просмотр изменений)

Сейчас «Карточка» для админа — это модалка `ChangeProjectDiffModal`, которая открывается из экрана `AdminClientChanges` (вкладка **«Изменения клиента»** внутри `AdminProjectsScreen`).

- **Поток**: `App.tsx` → `AdminProjectsScreen` → `AdminClientChanges` → кнопка **«Карточка»** → `ChangeProjectDiffModal`
- **Данные**: `GET /admin/changes/:clientId` возвращает элементы `AdminChange`, внутри есть:
  - `projectSnapshot` (что стало)
  - `beforeSnapshot` (что было)
  - `changedFields` (какие поля менять подсветкой)

Ключевое место, где открывается модалка:

```168:200:my-app-vite/src/components/AdminClientChanges.tsx
<button
  type="button"
  className="btn"
  style={{ marginLeft: 6 }}
  onClick={() => setSnapshotFor(c)}
  disabled={!c.projectSnapshot}
  title={c.projectSnapshot ? 'Открыть карточку' : 'Нет данных карточки'}

{snapshotFor && (
  <ChangeProjectDiffModal
```

А сама «карточка» берёт снапшоты/список изменённых полей и подсвечивает их:

Отдельно в проекте есть **вторая** реализация карточки: `ProjectSnapshotModal` — просто таблица всех ключей снапшота без “diff” (сейчас напрямую из админских изменений она не используется).

### Что сейчас хорошо и что можно улучшить

- **Хорошо**:
  - Быстро видно “что поменялось”: есть `changedFields` и подсветка.
  - Есть “Было:” для части полей и кнопка “Копировать JSON”.

- **Проблемные места (в основном UX/архитектура, риск: низкий–средний)**:
  - **Дублирование модалок**: много модалок с почти одинаковым оверлеем/стилями (и `ProjectSnapshotModal`, и `ChangeProjectDiffModal`, и другие).
  - **Доступность/управление**: нет закрытия по **Esc**, нет закрытия по клику на фон, нет фокус-трапа, фон не блокируется (скролл/фокус).
  - **Слабая типизация**: `Record<string, any>` + `changedFields: string[]` → легко “сломаться” при новых полях/форматах.
  - **Поддержка полей**: `ChangeProjectDiffModal` жёстко прошит под ограниченный список полей — если бэк добавит поле, в “карточке” его не будет видно вообще.
  - **Diff для массивов**: регионы/сайты/телефоны показываются списком, но не видно “добавили/удалили”.
  - **Статусные действия**: “Отметить выполненным” без индикатора загрузки на строке и с `alert` при ошибке.

---

### План улучшений (по этапам)

- **Этап 1 — быстрые улучшения (риск: низкий)**
  - **Сделать общий компонент `Modal`** и перевести на него все модалки: закрытие по Esc, клик по фону, блокировка скролла фона, базовая доступность (`aria-labelledby`, фокус на кнопку закрытия).
  - В `AdminClientChanges`:
    - добавить **локальный индикатор** “сохраняю…” на кнопке “Отметить выполненным” для конкретной строки,
    - заменить `alert` на аккуратный текст ошибки/тост.
  - В `ChangeProjectDiffModal`:
    - добавить “Копировать **Было** / **Стало**” (или вкладки),
    - унифицировать “Было:” для всех подсвеченных полей.

- **Этап 2 — улучшение поддержки и расширяемости (риск: средний)**
  - Переделать `ChangeProjectDiffModal` на **конфиг полей** (массив описаний полей: ключ, label, форматтер, как сравнивать/рисовать), чтобы не держать огромный JSX и проще добавлять новые поля.
  - Ввести тип `ProjectSnapshot` (опциональные поля) и аккуратный guard: `changedFields` приводить к `FieldKey[]` только если ключи известны.
  - Добавить переключатель **“Показывать только изменённые поля”** + “сырой JSON” (как дополнительная вкладка).

- **Этап 3 — “настоящий diff” и масштабирование (риск: средний–высокий, возможно нужен бэк)**
  - Для массивов (регионы/телефоны/сайты) показывать **добавлено / удалено** (либо считать на фронте через set-diff, либо попросить бэк отдавать структурированный diff).
  - Добавить фильтры/пагинацию по изменениям (когда изменений много): статус/action/дата/поиск, лучше с поддержкой на API.
